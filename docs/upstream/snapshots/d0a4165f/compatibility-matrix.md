## 판정 규칙

- 구현 상태 vocabulary
  - `Implemented/Tested`: production 경로와 대응 테스트가 둘 다 확인됨
  - `Implemented/Partial tests`: production 경로는 확인됐지만 테스트 범위가 일부 핵심 시나리오만 덮음
  - `Partial`: 공개 표면 또는 일부 실행 경로만 있고 핵심 invariants/대칭 구현이 비어 있음
  - `Docs-only`: 문서/ADR/README만 있고 해당 언어 production 코드 근거가 없음
  - `Language-only`: 반대 언어에는 있으나 이 언어엔 동등 surface가 없음
  - `Provider-specific`: 공통 core가 아니라 특정 provider/hosting/adapter package 안에만 있음
  - `Not found`: 이번 snapshot 근거에서 코드와 문서 모두 확인하지 못함
- `code-first 판정 및 핵심 drift`는 문서보다 pinned source를 우선한다. 문서와 코드가 충돌하면 코드 판정을 적고 drift를 명시했다.
- `upstream maturity`는 항상 `pkg:`와 `code:`를 분리해 적는다. `pkg:`는 csproj/pyproject/PACKAGE_STATUS 기준, `code:`는 decorator/attribute/obsolete/experimental marker 기준이다.
- `repo docs 상태`는 **이 저장소의 Java 문서화 수준**을 뜻한다. 현재 저장소는 실행 코드가 아니라 snapshot 분석 문서 단계이므로 대부분 `Docs-only`다.
- Java 목표는 현재 저장소의 `AgentEngine`/host 분리 원칙을 따른다. core runtime과 host adapter가 같은 책임을 중복 소유하지 않게 판정했다.
