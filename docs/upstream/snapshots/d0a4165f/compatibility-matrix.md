## Judgement rules

- Implementation status vocabulary
  - `Implemented/Tested`: both a production path and matching tests are confirmed
  - `Implemented/Partial tests`: the production path is confirmed but test coverage reaches only some of the core scenarios
  - `Partial`: only a public surface or part of an execution path exists, and the core invariants / symmetric implementation are empty
  - `Docs-only`: only documents/ADRs/READMEs exist, with no production code evidence in that language
  - `Language-only`: present in the opposite language but with no equivalent surface in this language
  - `Provider-specific`: present only inside a particular provider/hosting/adapter package rather than in the common core
  - `Not found`: neither code nor documentation could be confirmed in this snapshot's evidence
- `code-first judgement and core drift` gives the pinned source priority over documentation. When documentation and code conflict, the code judgement is written down and the drift is stated explicitly.
- `upstream maturity` is always written with `pkg:` and `code:` separated. `pkg:` is based on csproj/pyproject/PACKAGE_STATUS, and `code:` is based on decorator/attribute/obsolete/experimental markers.
- `repo docs status` means **the Java documentation level of this repository**. This repository is currently at the snapshot-analysis document stage rather than at executable code, so most values are `Docs-only`.
- The Java target follows this repository's `AgentEngine`/host separation principle. The judgements keep the core runtime and the host adapter from co-owning the same responsibility.

## Java scope by phase

| Phase | Scope |
| --- | --- |
| MVP/Core+ | The engine-owned scope covering single-agent execution, the message/content model, the model/tool loop, sessions/stores, middleware, observability, errors/security, the testkit, and a minimal provider vertical slice |
| Workflow | The scope to be split into a separate workflow subproject, such as graph/runtime/checkpoint/HITL/composition/orchestration/declarative |
| Hosting | The generic hosting core, protocol adapters, identity/session routing, and the host binder and state ownership boundary |
| Optional adapters | The scope that can ship as an independent artifact without core parity, such as code execution, DevUI, channels, and specific provider/managed runtimes |
