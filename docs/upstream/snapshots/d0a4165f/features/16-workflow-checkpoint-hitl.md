# 16-workflow-checkpoint-hitl

## 상태/스냅샷

- 이 문서는 워크플로 런타임 중에서도 **checkpoint/resume/persistence**, **request-response**, **HITL(human-in-the-loop)**, **approval flow**만 통합한다. 정적 그래프 정의나 일반 실행 루프는 별도 문서 범위로 보고, 여기서는 “중단 가능한 실행을 어떻게 저장하고, 외부 응답을 어떻게 받아 재개하는가”에 초점을 둔다. 중심 구현은 .NET의 `CheckpointManager`/`CheckpointableRunBase`/`ExternalRequest`/`ExternalResponse`/`RequestInfoExecutor`/`AIContentExternalHandler`/`InProcessRunner`와 Python의 `WorkflowCheckpoint`/`CheckpointStorage`/`Workflow.run(...responses/checkpoint_id...)`/`request_info()`/orchestration approval executors/declarative approval executors다. ([.NET CheckpointManager](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/CheckpointManager.cs#L11-L86), [.NET CheckpointableRunBase](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/CheckpointableRunBase.cs#L10-L49), [.NET ExternalRequest](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/ExternalRequest.cs#L10-L101), [.NET RequestInfoExecutor](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/RequestInfoExecutor.cs#L15-L170), [.NET AIContentExternalHandler](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/AIContentExternalHandler.cs#L14-L103), [Python WorkflowCheckpoint](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_checkpoint.py#L30-L99), [Python Workflow.run API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L683-L795))

## 목적·경계

### 목적

- 이 기능의 목적은 세 가지다.
  1. **실행 중 워크플로를 안전하게 저장하고 복원**한다.
  2. **외부 응답이 필요한 지점에서 실행을 중단하고 다시 이어서 수행**한다.
  3. **승인·인간 피드백·외부 도메인 검증 같은 human-in-the-loop 패턴을 일관된 request-response 계약으로 모델링**한다.  
  .NET은 request port와 checkpoint manager가 이 책임을 맡고, Python은 `request_info()`와 `WorkflowCheckpoint`, 그리고 orchestration/declarative 승인 executors가 같은 책임을 분담한다. ([.NET AddExternalCall helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/WorkflowBuilderExtensions.cs#L169-L191), [.NET RequestInfoExecutor purpose](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/RequestInfoExecutor.cs#L15-L31), [Python request_info context API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow_context.py#L403-L435), [Python declarative tool approval purpose](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_tools.py#L50-L83))

## 상세 실행 흐름

### 1. .NET 체크포인트 생성과 복원

- .NET `InProcessRunner.CheckpointAsync(...)`는 checkpoint manager가 있는 경우 먼저 executor checkpoint hooks를 호출하고, workflow definition snapshot을 캐시한 뒤, edge state export와 state publish를 거쳐 `RunnerStateData`, `stateData`, `edgeData`를 모아 internal `Checkpoint`를 만든다. 이 checkpoint는 마지막 checkpoint를 parent로 연결한다. ([CheckpointAsync flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/InProc/InProcessRunner.cs#L341-L369), [Checkpoint payload shape](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Checkpointing/Checkpoint.cs#L10-L40))
- 복원은 `RestoreCheckpointCoreAsync(...)`가 담당한다. 이 경로는 checkpoint lookup 후 workflow compatibility를 검사하고, `StateManager.ImportStateAsync(...)`, `RunContext.ImportStateAsync(...)`, executor restore hooks, edge-state import를 수행하며 checkpoint index를 다시 채운다. ([restore core flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/InProc/InProcessRunner.cs#L395-L438))
- live run에 대한 복원은 `AsyncRunHandle.RestoreCheckpointAsync(...)`가 event buffer를 먼저 비운 뒤 checkpointing handle restore를 호출하고, restore 이후 run loop를 깨운다. 스트리밍 resume 시작 경로는 `ResumeStreamAsync(...)`가 restore를 먼저 하고, event stream이 subscribe된 다음 pending request를 다시 발행하도록 `_needsRepublish` 플래그를 세운다. ([clear-buffer-then-restore](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Execution/AsyncRunHandle.cs#L187-L208), [resume stream with republish flag](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/InProc/InProcessRunner.cs#L166-L191), [republish consumption](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/InProc/InProcessRunner.cs#L198-L206))
- checkpoint manager의 “latest checkpoint” 판단은 store index ordering contract에 의존한다. `ICheckpointStore.RetrieveIndexAsync(...)`는 oldest-first, newest-last 순서를 반드시 보장해야 하며, `CheckpointManager.GetLatestCheckpointAsync(...)`는 마지막 요소를 latest로 취급한다. ([index ordering contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Checkpointing/ICheckpointStore.cs#L14-L30), [GetLatestCheckpointAsync](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/CheckpointManager.cs#L63-L86))

### 2. .NET request-response 코어 흐름

- .NET core request-response는 `RequestPort<TRequest,TResponse>`와 `ExternalRequest`/`ExternalResponse`를 중심으로 돈다. builder helper `AddExternalCall<TRequest,TResponse>(...)`는 source와 port 사이에 양방향 edge를 추가해 외부 call/response 경로를 만든다. ([RequestPort](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/RequestPort.cs#L13-L33), [AddExternalCall](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/WorkflowBuilderExtensions.cs#L169-L191))
- `RequestInfoExecutor`는 세 종류의 입력을 처리한다.
  1. raw request payload  
  2. wrapped `ExternalRequest`  
  3. wrapped `ExternalResponse`  
  request를 받으면 `RequestSink.PostAsync(request)`로 외부에 내보내고, wrapped request의 경우 original request를 `_wrappedRequests`에 저장해 나중 response를 rewrap할 수 있게 한다. ([RequestInfoExecutor routes](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/RequestInfoExecutor.cs#L38-L60), [HandleCatchAll/HandleAsync request paths](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/RequestInfoExecutor.cs#L65-L119))
- response가 들어오면 `HandleAsync(ExternalResponse)`가 port compatibility와 response type을 검증한다. wrapped request를 기억하고 있으면 original request 형태로 rewrap하여 workflow에 다시 보내고, 아니면 wrapped response와 unwrapped response payload를 둘 다 workflow로 보낸다. 또한 `_wrappedRequests`는 checkpoint save/restore 대상이다. ([response handling and rewrap](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/RequestInfoExecutor.cs#L121-L170))

## 동시성·스트리밍·취소

- .NET 스트리밍 run은 `WatchStreamAsync(blockOnPendingRequest: false)`를 쓰면 pending request가 생긴 시점에 control을 caller에게 돌려준다. 이 모드가 checkpoint/resume과 HITL turn loop에 적합하다. request가 pending인 동안 caller가 `SendResponseAsync(...)`로 응답을 넣으면 다시 run loop가 진행된다. ([blockOnPendingRequest semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/StreamingRun.cs#L80-L100), [SendResponseAsync](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/StreamingRun.cs#L38-L45))
- .NET pending approval re-emission은 idempotent로 처리된다. 같은 request id가 checkpoint restore 후 다시 나타나도 `AIContentExternalHandler`는 duplicate repost를 하지 않는다. 이는 same pending request의 다중 생성 race를 방지한다. ([idempotent pending request re-emission](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/AIContentExternalHandler.cs#L59-L71))
- Python은 `responses + checkpoint_id` 조합을 한 번의 `run(...)`에서 처리할 수 있고, 이때 restore 중 재발행될 request_info event 중 caller가 이미 응답을 제공한 것들은 stream에서 다시 보여 주지 않는다. 즉 restore-then-send 응답 경로의 duplicate event 노출을 막는다. ([restore+responses path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L974-L1010), [skip already-handled request_info events](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L883-L891))
- Python declarative approval flow의 concurrency 안전성은 테스트가 고정한다. 동일 executor에 두 approval request가 pending이어도 각 response는 자기 `original_request` payload에 바인딩되어 swap되지 않는다. ([concurrent approvals do not swap](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L186-L205))
- 취소 측면에서 `.NET`은 public cancel surface를 제공하지만, 이 문서 범위에서 checkpoint/HITL flow 자체는 cancel보다 resume/response가 핵심이다. Python core inspected path는 public cancel보다 request/response continuation과 checkpoint replay를 더 강하게 강조한다. ([.NET cancel surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/StreamingRun.cs#L102-L107), [Python run continuation semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L723-L739))

## Java 결정

- Java는 checkpoint와 HITL을 **동일 continuation contract** 위에 올리는 것이 좋다. 즉 “pending external requests + in-flight responses + shared state + executor snapshots”를 하나의 checkpoint object에 같이 넣고, restore 후 pending requests를 재발행하는 식이다. .NET과 Python 모두 이 모델을 취한다. ([.NET checkpoint payload](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Checkpointing/Checkpoint.cs#L10-L40), [Python WorkflowCheckpoint payload](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_checkpoint.py#L30-L99))
- Java는 Python-style warning-only overlap보다 **기본적으로 pending request가 남아 있으면 fresh message를 금지**하는 정책을 추천한다. 필요한 경우에만 opt-in override를 두는 편이 더 안전하다. Python test가 보여 주듯 overlap은 old response가 moved-on state에 적용되는 위험이 있다. ([Python overlap warning code](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L847-L872), [Python overlap behavior test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/workflow/test_workflow.py#L113-L143))
- Java approval flow는 **original request payload immutable contract**를 기본으로 해야 한다. resume 시 side-channel state를 다시 읽는 방식보다 `original_request`를 유일한 근거로 삼는 Python declarative contract가 더 안전하고 concurrency에도 강하다. ([Python original_request contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L7-L21), [concurrent approvals do not swap](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L186-L205))
- Java file-based checkpoint storage는 Python처럼 path traversal validation과 allowed-type whitelist를 기본 내장해야 한다. 단순 JSON/Java serialization만으로는 unsafe하다. ([Python file path guard](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_checkpoint.py#L292-L310), [Python restricted decode](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_checkpoint.py#L362-L369))
- Java는 run handle에 `resumeFrom(checkpointId)`, `respond(requestId, payload)`, `listPendingRequests()`, `latestCheckpoint()` 같은 1급 API를 제공하는 편이 좋다. .NET의 handle-oriented API와 Python의 unified API를 절충하되, 운영 제어는 handle에 모으는 쪽이 낫다. ([.NET CheckpointableRunBase](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/CheckpointableRunBase.cs#L23-L48), [Python unified run params](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_workflow.py#L721-L740))

## 구체 acceptance scenarios

1. **checkpoint latest lookup는 commit order를 따른다.**  
   store가 oldest-first/newest-last 순서를 보장하면 `GetLatestCheckpointAsync()`가 마지막 항목을 latest로 돌려준다. ([ICheckpointStore ordering contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/Checkpointing/ICheckpointStore.cs#L21-L30), [GetLatestCheckpointAsync](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows/CheckpointManager.cs#L73-L86))

2. **pending request가 있는 checkpoint에서 resume하면 request_info가 다시 보여야 한다.**  
   .NET은 fresh handle resume 후 `RequestInfoEvent`를 재발행해야 하고, 테스트가 이를 고정한다. ([republish pending requests test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Workflows.UnitTests/CheckpointResumeTests.cs#L20-L85))

3. **resume 직후 상태는 pending requests를 반영해야 한다.**  
   .NET resumed handle의 `RunStatus`는 `PendingRequests`여야 한다. ([resumed status test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Workflows.UnitTests/CheckpointResumeTests.cs#L87-L138))

4. **forged response는 request id가 맞아도 port id가 다르면 거부해야 한다.**  
   reject 후에도 legitimate responder는 정상 completion이 가능해야 한다. ([forged response rejection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Workflows.UnitTests/ExternalResponsePortCorrelationTests.cs#L34-L59), [legitimate response still works](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Workflows.UnitTests/ExternalResponsePortCorrelationTests.cs#L61-L84))

5. **tool approval deny는 tool invocation을 실행하지 않아야 한다.**  
   Python declarative approval response가 `approved=False`면 rejection result만 state에 저장하고 `ActionComplete`로 넘어가야 한다. ([tool denial path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_tools.py#L526-L546))

6. **tool approval resume는 original_request payload를 source-of-truth로 써야 한다.**  
   stale old state가 있어도 payload가 이겨야 하고, concurrent approvals도 swap되지 않아야 한다. ([approval payload test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L170-L184), [concurrent approval test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L186-L205), [stale state poison ignored](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L207-L220))

7. **agent approval에서 empty follow-up은 approve, non-empty follow-up은 iterate로 해석해야 한다.**  
   orchestration `AgentRequestInfoExecutor`는 empty message list면 original response를 yield하고, message list가 있으면 새 agent request를 보낸다. ([approval vs iterate semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/orchestrations/agent_framework_orchestrations/_orchestration_request_info.py#L103-L117), [tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/orchestrations/tests/test_orchestration_request_info.py#L131-L179))

8. **declarative external loop는 user input 또는 agent response가 loop condition을 false로 만들면 cleanly 종료해야 한다.**  
   종료 시 external loop state를 지우고 `ActionComplete`를 보내 다음 action으로 넘어가야 한다. ([loop exit before invoke](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_agents.py#L921-L936), [loop exit after agent response](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_agents.py#L973-L992))

9. **checkpoint file path는 storage root 밖으로 나가면 안 된다.**  
   Python file storage는 malicious checkpoint id를 path validation으로 거부해야 한다. ([path traversal guard](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_workflows/_checkpoint.py#L292-L310))

10. **subworkflow request-response도 parent workflow 경계를 넘어 correlation되어야 한다.**  
    Python `WorkflowExecutor`/`SubWorkflowRequestMessage` 패턴은 parent가 cache hit로 즉시 응답하거나 external response를 받아 child workflow에 되돌려 보내는 시나리오를 지원해야 한다. ([subworkflow basic flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/workflow/test_sub_workflow.py#L179-L239), [intercept and forward flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/workflow/test_sub_workflow.py#L241-L328))
