# 08-sessions

This document covers only the **session surface** of Agent Framework snapshot `d0a4165f`. The scope is `AgentSession` identity/state, create/serialize/deserialize, the `.NET` `ChatClientAgentSession`, the Python `SessionStore`/`FileSessionStore`, the snapshot schema/version/type registry, concurrency/persistence/corrupt snapshot quarantine, `ServiceSessionId`, and the hosted authorization boundary. The detailed behavior of `HistoryProvider`/`ContextProvider`/message injection belongs to document 09, so only the boundary with the session is described here. [Python sessions module](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L3-L14) [Python HistoryProvider boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L909) [.NET AgentSession remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L16-L52)

## State/snapshot

- The default session abstraction of `.NET` is `AgentSession`, and the common state is stored in `StateBag`. `ChatClientAgentSession` adds an optional `ConversationId` on top to express service-managed chat history continuation. It is documented that a serialized session may contain conversation content, identifiers, and PII. [AgentSession state/security](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L39-L52) [AgentSession StateBag](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L76-L85) [ChatClientAgentSession conversation state](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L25-L65)
- The Python `AgentSession` is a lightweight container holding only a local `session_id`, an opaque `service_session_id`, and a mutable `state` dict. It states explicitly that `service_session_id` is a provider-issued continuation handle but is not an end-user authorization boundary. [AgentSession fields and auth-boundary note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1649)
- The Python durable snapshot envelope is fixed as the single internal `_SessionSnapshot`, whose fields are `type="session"`, `session_id`, `service_session_id`, `state`, and `version="1.0"`. The JSON and MessagePack encoder/decoder share the same envelope. [Session snapshot schema](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L458-L493)
- The reviewed `.NET` core session serialization is the plain JSON object round trip of `ChatClientAgentSession.Serialize/Deserialize`, and the Foundry `FileSystemAgentSessionStore` likewise stores the `JsonElement` the agent produced straight into a file and returns it to the agent after `JsonDocument.Parse`. Within the inspected scope, a Python-style explicit snapshot `version` envelope or corrupt-snapshot quarantine cannot be confirmed on the `.NET` core session path. [ChatClientAgentSession serialize/deserialize](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L67-L89) [FileSystemAgentSessionStore save/load](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L149-L231)

## Purpose and boundary

- The primary purpose of a session is to carry multi-turn conversation state across future runs, HTTP requests, and process restarts across runtime boundaries. In `.NET` the `AIAgent` creates the session and owns the serialize/deserialize entrypoints. In Python, `BaseAgent.create_session()`/`get_session()` distinguish a local session from a service-managed continuation session. [AgentSession lifecycle remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L30-L43) [BaseAgent create/get session](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506)
- The `.NET` `AgentSession` directly leaves open, in the comments of the session abstraction, the possibility of attaching behavior such as storage customization, data extraction/injection, and history reduction. The detailed implementation of that behavior, however, is handled by the agent/provider/middleware rather than by the session class. [AgentSession behavior scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L24-L37)
- The Python `HistoryProvider` can store messages in `AgentSession.state` or connect to external storage, but the detailed load/store pipeline is provider territory. This document records only the boundary that “a provider putting custom state into a session must call `register_state_type()` at module import time”. [HistoryProvider boundary and registration rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L899)
- The core of the Python ADR is that `service_session_id` must be “an opaque continuation handle that connects future service calls” rather than a generic correlation field. Task identity, message/response identity, and the continuation token do not share the same lifetime, so they must not be mixed into the session. [ADR-0029 context/problem](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L14-L39) [ADR-0029 lifecycle split decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L243-L267)

## Maturity

- The Python `SessionStore` and `FileSessionStore` are both marked experimental with `ExperimentalFeature.SESSION_STORE`. The production decorator and the tests verify the same feature id/stage. [Experimental SessionStore decorator](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1705) [Experimental FileSessionStore decorator](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1769-L1797) [Experimental tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_sessions.py#L855-L862)

The maturity of the core chat session surface therefore differs from that of the hosted persistence/isolation surface. [AgentSession public surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L55-L59) [ChatClientAgentSession public surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L11-L16) [Foundry AgentSessionStore experimental](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/AgentSessionStore.cs#L11-L20) [HostedSessionContext experimental](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContext.cs#L31-L32)

[ADR-0034 status](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L1-L6) [ADR-0034 outcome](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L190-L279) [Implemented store code](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1975)

## Public APIs and types

### Python

- `ServiceSessionId` is a `Mapping[str, Any]` type alias, and `AgentSession` exposes `session_id`, `service_session_id`, and `state`. `_SessionSnapshot` and `_SessionStatePayload` are internal persistence DTOs. [ServiceSessionId and snapshot internals](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L68-L75) [AgentSession public fields](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1689) [Snapshot DTO](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L458-L493)
- `register_state_type(cls, type_id, encoder, decoder)` registers a stable type id and a codec pair in a process-wide registry. Default codecs are provided for `to_dict`/`from_dict` classes and for Pydantic models. [register_state_type contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335)
- `BaseAgent.create_session()` creates a lightweight local session and `BaseAgent.get_session()` creates a service-managed continuation session. The generic chat path does not forward a structured `service_session_id` and blocks it as an error. [BaseAgent create/get session](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506) [Structured service_session_id rejection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L529)
- `SessionStore` is the in-memory default plus an extension point, and `FileSessionStore` is a JSON/MessagePack file-backed subclass. [SessionStore API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1766) [FileSessionStore API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1769-L1982)

## Detailed execution flow

### Python

1. `BaseAgent.create_session()` creates a plain `AgentSession(session_id=...)`, and `get_session()` creates an `AgentSession` with `service_session_id` injected. [BaseAgent create/get flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506)
2. `AgentSession.to_dict()` builds `{type, session_id, service_session_id, state}` and sends `state` down through `_serialize_state()`. `from_dict()` restores it through `_deserialize_state()`. [AgentSession to_dict/from_dict](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1655-L1689) [Shared state serializer](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L348-L455)
3. On a registry hit, `_serialize_value()` forces the codec output to carry the stable `type` tag, and `_deserialize_value()` calls the matching decoder. A decoder failure is wrapped in a `ValueError` so that it can be handed to store recovery. [Serialize typed values](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L348-L403) [Deserialize typed values](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L406-L455)
4. `SessionStore.set()` stores a deepcopy snapshot and `get()` returns a deepcopy working copy again, so that a branch-like continuation cannot pollute the stored copy. [In-memory branching semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1693-L1766)
5. `FileSessionStore.set()` allows exactly `type(session) is AgentSession`, copies the `service_session_id` mapping into a plain dict, serializes it with `_SessionSnapshot` plus the msgspec encoder, and performs an atomic replace with a temp file plus `os.replace()`. [FileSessionStore write path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1893-L1924)
6. `FileSessionStore.get()` proceeds in the order bytes read → typed msgspec decode → `version` check → `state` mapping check → `_deserialize_state()` → new `AgentSession` reconstruction. Only parse corruption is a quarantine target; schema/version/decoder problems leave the file in place. [FileSessionStore read path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1839-L1891) [Quarantine helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1952-L1968)
7. The generic chat agent path forwards `service_session_id` as a provider conversation continuation only when it is a string, and throws an early error for a structured mapping. The default OTel `gen_ai.conversation.id` extraction is also string-only. [Chat continuation forwarding rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L541)

### .NET

1. `ChatClientAgent.CreateSessionAsync(string conversationId)` immediately creates a `ChatClientAgentSession` with `ConversationId` filled in. [CreateSessionAsync typed overload](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L430-L445)
2. `SerializeSessionCoreAsync()` blocks a runtime type that is not `ChatClientAgentSession` with an `InvalidOperationException` before the remote call. `DeserializeSessionCoreAsync()` conversely calls only `ChatClientAgentSession.Deserialize()`. [ChatClientAgent session type gate](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L447-L463)
3. `ChatClientAgentSession.Deserialize()` first checks whether the input is a JSON object, and then materializes the session with the source-generated `AgentJsonUtilities.DefaultOptions` type info. `Serialize()` uses the same type info. [ChatClientAgentSession serialization flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L67-L89) [AgentJsonUtilities options](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AgentJsonUtilities.cs#L14-L59)
4. On the Foundry hosted path the response handler resolves the user identity first, performs the partitioned `AgentSessionStore` lookup with that user id, and then stamps or validates the `HostedSessionContext` on the loaded-or-created session. A mismatch is a 403, and a null identity in hosted production is a hard error. [Hosted load/stamp/validate flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/AgentFrameworkResponseHandler.cs#L91-L170)
5. The same handler rejects a session whose `ChatClientAgentSession.ConversationId` is already filled in on the hosted responses path. Hosted session persistence and chat-client service-managed history therefore do not coexist on the same request path. [Hosted service-managed-history rejection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/AgentFrameworkResponseHandler.cs#L172-L182)

## State and persistence

- The `.NET` `StateBag` stands on a `ConcurrentDictionary<string, AgentSessionStateBagValue>`, and each per-entry value holds a `JsonElement` together with a deserialized cache and performs lazy serialize/deserialize. [StateBag storage model](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs#L21-L45) [StateBagValue dual representation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBagValue.cs#L15-L67)
- The `.NET` `AgentSessionStateBag.Serialize()`/`Deserialize()` round-trips the dictionary payload itself as a JSON object, without a wrapper object. [StateBag serialize/deserialize](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs#L119-L145)
- The Python `AgentSession.state` is a plain `dict[str, Any]`, but on the durable path `_SessionStatePayload.serialize()` enforces `_serialize_state()` and `_validate_durable_state_value()` to satisfy the “JSON-compatible plus restorable” condition. [State payload validation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L428-L470)
- Because Python pre-registers `Message` in the default registry, the default message payload a `HistoryProvider` put into session state enters the snapshot without additional registration. [Message pre-registration](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L496-L497) [HistoryProvider note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L891-L899)
- The `.NET` Foundry `FileSystemAgentSessionStore` separates persisted sessions with a `{root}/a-{agent}/u-{user}/c-{conversation}.json` structure. When `userId == null` only the `u-` layer collapses. [FileSystemAgentSessionStore path layout](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L234-L283) [Foundry AgentSessionStore userId contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/AgentSessionStore.cs#L22-L70)

## Extension points

- For Python custom state extension, `register_state_type()` is the canonical way. A stable type id collision is rejected immediately, and an encoder/decoder can only be registered as a pair. Registration at module import time is the premise for cold-start restore. [register_state_type extension contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335)
- A Python custom durable store is extended by overriding `SessionStore.get/set/delete`. This also matches the ADR direction that the base type is a concrete default implementation and at the same time an extension point. [SessionStore overridable methods](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1766) [ADR-0034 store ownership decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L192-L203)
- An agent that uses a structured Python `service_session_id` must override `_get_otel_conversation_id()` to keep primary conversation id extraction an agent-owned decision. The ADR 0029 decision is that generic telemetry code must not parse a structured mapping. [BaseAgent default OTel extraction](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L531-L541) [ADR-0029 OTel extraction rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L265-L344)
- The default pattern for `.NET` session extension is to expose a session-wrapped service lookup or typed state through `GetService()` and `StateBag`. Hosted identity is attached not as a separate wrapper subclass but as a write-once `HostedSessionContext` extension stored under a `StateBag` key. [AgentSession GetService](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L87-L115) [HostedSessionContextExtensions write-once extension](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContextExtensions.cs#L15-L80)
- Because the `.NET` `ChatClientAgentSession` is sealed, putting generic hosted identity in as a subtype wrapper does not fit the current code. Because of this constraint, ADR 0026 also explicitly rejected the wrapper option. ## Concurrency and cancellation

- The `.NET` `AgentSessionStateBag` puts thread safety front and centre: the storage is a `ConcurrentDictionary` and per-value mutation/read is protected by an internal lock. The unit tests confirm that concurrent writes, concurrent serialize, and concurrent reads plus writes do not throw. [StateBag thread-safe design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs#L11-L19) [StateBagValue lock](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBagValue.cs#L13-L18) [Concurrent tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AgentSessionStateBagTests.cs#L471-L547)
- The `.NET` `FileSystemAgentSessionStore` has no per-session lock and prevents only torn writes with a unique temp file plus an overwrite rename. Both the comment and the test describe the semantics as “no partial file is visible, last writer wins”. [Atomic write comment](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L39-L42) [SaveSessionAsync temp-file flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L158-L181) [Concurrent temp-file test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Foundry.Hosting.UnitTests/FileSystemAgentSessionStoreTests.cs#L187-L206)
- The `.NET` hosted store APIs take a `CancellationToken`. The read path passes the token to `File.ReadAllBytesAsync(..., cancellationToken)`, and both save and load pass the token to the agent serialize/deserialize call. Because the rename/delete itself is a synchronous filesystem step, a finer-grained cancel point cannot be confirmed. [Foundry store cancellation path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L149-L231)
- The Python `SessionStore` provides deepcopy-based branch isolation, so concurrent continuations do not share-mutate the stored snapshot. [SessionStore deepcopy semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1724-L1754) [Deepcopy tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_sessions.py#L868-L894)
- The Python `FileSessionStore` uses 64 striped process-local locks and hands read/write/delete to `asyncio.to_thread()`. Operations are serialized within the same file path hash bucket, no cross-process/host coordination is performed, and the semantics are last-writer-wins. [Striped lock design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1799-L1805) [Security/concurrency remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1776-L1796) [to_thread read/write/delete](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1839-L1936)
- The Python session-store APIs have no explicit cancellation token. There is an async surface, but the blocking filesystem work runs inside the thread offload, and a mid-thread-body cancellation hook cannot be confirmed in the inspected code. [Python session-store method signatures](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1724-L1766) [Python file-store thread offload](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1839-L1936)

## Java design decisions

### Decision 1. Java separates the local session id from the service continuation id

The Java `AgentSession` must also separate a local `sessionId` from an opaque `serviceSessionId` as Python does. `serviceSessionId` may allow both the string common case and the structured continuation case, but it must not be treated as an end-user authorization boundary. [Python AgentSession contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1649) [ADR-0029 lifecycle split](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L243-L267)

### Decision 2. The Java in-memory store makes branch-safe snapshot semantics the default

The deepcopy-on-set/get semantics of the Python `SessionStore` have the advantage that a concurrent continuation or a branch-like replay does not pollute the stored copy. It is safe for Java too that `get()` does not return a live reference. [Python SessionStore deepcopy semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1724-L1754) [Deepcopy tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_sessions.py#L868-L894)

### Decision 3. A Java durable snapshot enforces a typed envelope plus an explicit version

The `{type, version, session_id, service_session_id, state}` envelope of the Python `_SessionSnapshot` is better for migration/validation than the `.NET` plain object round trip. Java is better off putting an explicit `type`/`version` header into the JSON default and adding an optional binary codec on top. [Python snapshot envelope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L473-L493) [ADR-0034 msgspec envelope decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L234-L266) [.NET plain session object round-trip](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L67-L89)

### Decision 4. Java custom session state is restored through a stable type-id registry

In Java too it is hard to cold-start restore provider-owned custom state with the default JSON mapper alone. An explicit codec registry, collision rejection, a default `toMap/fromMap`-style codec, and pre-registration of framework-owned known types such as `Message` are needed. [Python registry rules](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335) [Python Message pre-registration](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L496-L497)

### Decision 5. Java corrupt-snapshot recovery quarantines only parse corruption and preserves a schema/version mismatch

Python's selective quarantine policy is operationally well balanced. It quarantines only when the bytes themselves are broken, and preserves the original on a schema/version/decoder failure to allow a rollback or a compatible reader. Java is better off following the same distinction. [Python quarantine branch](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1851-L1871) [Python preserve-on-version/schema/decoder-failure](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1872-L1889) [ADR-0034 quarantine decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L276-L279)

### Decision 6. Java hosted persistence separates the service continuation from the tenant boundary

A hosted multi-tenant Java layer must have a write-once hosted identity context and a physical path partition separately, as `.NET` Foundry does. `serviceSessionId` is a continuation, and the tenant boundary must be handled by the hosted `userId`/agent partition. [HostedSessionContext write-once/read-only](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContextExtensions.cs#L15-L80) [Foundry path partition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L234-L310) [ADR-0031 defense-in-depth rationale](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0031-hosted-per-user-session-storage-isolation.md#L14-L39)

### Decision 7. A Java agent-specific session subtype must have an early compatibility gate

The reason the `.NET` `ChatClientAgent` checks the session type strongly before serialize, and the Python generic chat path early-rejects a structured `service_session_id`, is “to avoid dragging a wrong session shape all the way to a remote call”. Java must also check agent/session compatibility immediately at the run entrypoint. [`.NET` session-type gate](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L447-L458) [Python generic-chat continuation gate](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L529)
