# 08-sessions

이 문서는 Agent Framework snapshot `d0a4165f`의 **session surface**만 다룬다. 범위는 `AgentSession` identity/state, create/serialize/deserialize, `.NET` `ChatClientAgentSession`, Python `SessionStore`/`FileSessionStore`, snapshot schema/version/type registry, concurrency/persistence/corrupt snapshot quarantine, `ServiceSessionId`와 hosted authorization boundary다. `HistoryProvider`/`ContextProvider`/message injection의 세부 동작은 09 문서 범위이므로 여기서는 session과의 경계만 설명한다. [Python sessions module](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L3-L14) [Python HistoryProvider boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L909) [.NET AgentSession remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L16-L52)

## 상태/스냅샷

- `.NET`의 기본 session abstraction은 `AgentSession`이며, 공통 상태는 `StateBag`에 저장된다. `ChatClientAgentSession`은 여기에 optional `ConversationId`를 추가해 service-managed chat history continuation을 표현한다. serialized session은 conversation content, identifiers, PII를 포함할 수 있다고 문서화되어 있다. [AgentSession state/security](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L39-L52) [AgentSession StateBag](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L76-L85) [ChatClientAgentSession conversation state](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L25-L65)
- Python `AgentSession`은 local `session_id`, opaque `service_session_id`, mutable `state` dict만 가진 lightweight container다. `service_session_id`는 provider-issued continuation handle이지만 end-user authorization boundary는 아니라고 명시한다. [AgentSession fields and auth-boundary note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1649)
- Python durable snapshot envelope는 internal `_SessionSnapshot` 하나로 고정되며 필드는 `type="session"`, `session_id`, `service_session_id`, `state`, `version="1.0"`이다. JSON과 MessagePack encoder/decoder가 같은 envelope를 공유한다. [Session snapshot schema](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L458-L493)
- reviewed `.NET` core session serialization은 `ChatClientAgentSession.Serialize/Deserialize`의 plain JSON object round-trip이고, Foundry `FileSystemAgentSessionStore`도 agent가 만든 `JsonElement`를 그대로 파일에 저장했다가 `JsonDocument.Parse` 후 agent에 되돌린다. inspected 범위에서 Python식 explicit snapshot `version` envelope나 corrupt-snapshot quarantine는 `.NET` core session path에서는 확인 불가다. [ChatClientAgentSession serialize/deserialize](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L67-L89) [FileSystemAgentSessionStore save/load](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L149-L231)

## 목적·경계

- session의 1차 목적은 multi-turn conversation state를 future runs, HTTP requests, process restarts across runtime boundaries에서 이어 붙이는 것이다. `.NET`에서는 `AIAgent`가 session을 만들고 serialize/deserialize entrypoint를 소유한다. Python에서는 `BaseAgent.create_session()`/`get_session()`이 local session과 service-managed continuation session을 구분한다. [AgentSession lifecycle remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L30-L43) [BaseAgent create/get session](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506)
- `.NET` `AgentSession`은 storage customization, data extraction/injection, history reduction 같은 behavior attachment 가능성을 session abstraction 주석에 직접 열어 둔다. 하지만 behavior 자체의 세부 구현은 session class가 아니라 agent/provider/middleware가 담당한다. [AgentSession behavior scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L24-L37)
- Python `HistoryProvider`는 messages를 `AgentSession.state`에 저장하거나 외부 저장소와 연결할 수 있지만, 세부 load/store pipeline은 provider 영역이다. 이 문서에서는 “custom state를 session에 넣는 provider는 module import 시점에 `register_state_type()`을 호출해야 한다”는 경계만 기록한다. [HistoryProvider boundary and registration rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L899)
- `service_session_id`는 generic correlation field가 아니라 “future service calls를 이어 주는 opaque continuation handle”이어야 한다는 것이 Python ADR의 핵심이다. task identity, message/response identity, continuation token은 같은 수명주기를 갖지 않으므로 session에 섞어 넣으면 안 된다. [ADR-0029 context/problem](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L14-L39) [ADR-0029 lifecycle split decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L243-L267)

## 성숙도

- Python `SessionStore`와 `FileSessionStore`는 둘 다 `ExperimentalFeature.SESSION_STORE`로 marked experimental이다. production decorator와 test가 같은 feature id/stage를 검증한다. [Experimental SessionStore decorator](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1705) [Experimental FileSessionStore decorator](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1769-L1797) [Experimental tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_sessions.py#L855-L862)
- `.NET` `AgentSession`/`ChatClientAgentSession` 자체에는 experimental attribute가 보이지 않지만, Foundry hosting의 `AgentSessionStore`, `HostedSessionContext`, `HostedSessionContextExtensions`, `PlatformHostedSessionIsolationKeyProvider`, `FileSystemAgentSessionStore`는 experimental이다. 즉 core chat session surface와 hosted persistence/isolation surface의 성숙도가 다르다. [AgentSession public surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L55-L59) [ChatClientAgentSession public surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L11-L16) [Foundry AgentSessionStore experimental](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/AgentSessionStore.cs#L11-L20) [HostedSessionContext experimental](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContext.cs#L31-L32)

[ADR-0034 status](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L1-L6) [ADR-0034 outcome](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L190-L279) [Implemented store code](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1975)

## 공개 API·타입

### Python

- `ServiceSessionId`는 `Mapping[str, Any]` type alias이고, `AgentSession`은 `session_id`, `service_session_id`, `state`를 공개한다. `_SessionSnapshot`과 `_SessionStatePayload`는 internal persistence DTO다. [ServiceSessionId and snapshot internals](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L68-L75) [AgentSession public fields](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1689) [Snapshot DTO](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L458-L493)
- `register_state_type(cls, type_id, encoder, decoder)`는 process-wide registry에 stable type id와 codec pair를 등록한다. default codec은 `to_dict`/`from_dict` class와 Pydantic model에 제공된다. [register_state_type contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335)
- `BaseAgent.create_session()`은 lightweight local session을, `BaseAgent.get_session()`은 service-managed continuation session을 만든다. generic chat path에서는 structured `service_session_id`를 forwarding하지 않고 에러로 막는다. [BaseAgent create/get session](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506) [Structured service_session_id rejection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L529)

[SessionStore API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1766) [FileSessionStore API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1769-L1982)

## 상세 실행 흐름

### Python

1. `BaseAgent.create_session()`은 plain `AgentSession(session_id=...)`를, `get_session()`은 `service_session_id`를 주입한 `AgentSession`을 만든다. [BaseAgent create/get flow](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L506)
2. `AgentSession.to_dict()`는 `{type, session_id, service_session_id, state}`를 만들고 `state`는 `_serialize_state()`로 내려 보낸다. `from_dict()`는 `_deserialize_state()`로 역복원한다. [AgentSession to_dict/from_dict](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1655-L1689) [Shared state serializer](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L348-L455)
3. registry hit 시 `_serialize_value()`는 codec output에 stable `type` tag를 강제로 맞추고, `_deserialize_value()`는 matching decoder를 호출한다. decoder failure는 store recovery로 넘기기 위해 `ValueError`로 감싼다. [Serialize typed values](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L348-L403) [Deserialize typed values](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L406-L455)
4. `SessionStore.set()`은 deepcopy snapshot을 저장하고, `get()`은 다시 deepcopy working copy를 돌려줘 branch-like continuation이 저장본을 오염시키지 못하게 한다. [In-memory branching semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1693-L1766)
5. `FileSessionStore.set()`은 정확히 `type(session) is AgentSession`만 허용하고, `service_session_id` mapping을 plain dict로 복사한 뒤 `_SessionSnapshot` + msgspec encoder로 직렬화하고 temp file + `os.replace()`로 atomic replace한다. [FileSessionStore write path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1893-L1924)
6. `FileSessionStore.get()`은 bytes read → typed msgspec decode → `version` check → `state` mapping check → `_deserialize_state()` → new `AgentSession` reconstruction 순서다. parse corruption만 quarantine 대상이고, schema/version/decoder 문제는 파일을 남겨 둔다. [FileSessionStore read path](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1839-L1891) [Quarantine helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1952-L1968)
7. generic chat agent path는 `service_session_id`가 string일 때만 provider conversation continuation으로 forward하고, structured mapping이면 early error를 던진다. OTel `gen_ai.conversation.id` default extraction도 string-only다. [Chat continuation forwarding rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L541)

## 상태·영속화

- `.NET` `StateBag`는 `ConcurrentDictionary<string, AgentSessionStateBagValue>` 위에 서고, per-entry value는 `JsonElement`와 deserialized cache를 같이 들고 lazy serialize/deserialize를 수행한다. [StateBag storage model](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs#L21-L45) [StateBagValue dual representation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBagValue.cs#L15-L67)
- `.NET` `AgentSessionStateBag.Serialize()`/`Deserialize()`는 wrapper object 없이 dictionary payload 자체를 JSON object로 round-trip한다. [StateBag serialize/deserialize](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs#L119-L145)
- Python `AgentSession.state`는 plain `dict[str, Any]`지만, durable path에서는 `_SessionStatePayload.serialize()`가 `_serialize_state()`와 `_validate_durable_state_value()`를 강제해 “JSON-compatible + restorable” 조건을 맞춘다. [State payload validation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L428-L470)
- Python은 `Message`를 기본 registry에 선등록하므로 `HistoryProvider`가 session state에 넣은 기본 message payload는 추가 registration 없이 snapshot에 들어간다. [Message pre-registration](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L496-L497) [HistoryProvider note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L891-L899)

## 문서-코드 차이

### 1. Python session-store ADR는 `proposed`지만 code는 이미 구현됐다

ADR 0034는 status가 아직 `proposed`인데, production code에는 이미 core `SessionStore`, `FileSessionStore`, msgspec JSON/MessagePack snapshot, versioned envelope, registry validation, selective quarantine가 존재한다. 이 snapshot에서는 **코드가 더 authoritative**하다. [ADR-0034 status](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L1-L6) [ADR-0034 decisions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L190-L279) [Implemented code](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1692-L1975)

### 2. ADR 0026의 historical design은 `UserId + ChatId`였지만 현재 runtime type은 user-only다

ADR 0026은 superseded historical record이고 `HostedSessionContext`가 originally `UserId`와 `ChatId`를 다루었다고 설명한다. 그러나 현재 runtime `HostedSessionContext`는 protocol 2.0.0 기준 user-only type이며, chat-level isolation은 platform concern으로 내려갔다. [ADR-0026 superseded note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0026-hosted-session-identity-context.md#L1-L12) [ADR-0026 original type table](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0026-hosted-session-identity-context.md#L50-L59) [Current HostedSessionContext user-only remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContext.cs#L13-L29)

### 3. Sample docs는 persistence를 high-level로 설명하지만 snapshot schema/version/quarantine은 거의 설명하지 않는다

`.NET` persisted conversation sample은 “JSON save/load and resume”를 말하지만 agent-type compatibility gate, hosted user partition, corruption handling은 언급하지 않는다. Python conversation samples README도 history-provider patterns를 중심으로 설명하며 `FileSessionStore` snapshot schema/version/quarantine는 다루지 않는다. [Dotnet persisted conversation sample README](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/samples/02-agents/AgentProviders/foundry/Agent_Step06_PersistedConversations/README.md#L1-L31) [Python conversation samples README](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/samples/02-agents/conversations/README.md#L1-L18) [Actual `.NET` type gate and hosted boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L447-L458) [Actual Python snapshot/quarantine logic](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1839-L1891)

## Java 설계 결정

### 결정 1. Java는 local session id와 service continuation id를 분리한다

Java `AgentSession`도 Python처럼 local `sessionId`와 opaque `serviceSessionId`를 분리해야 한다. `serviceSessionId`는 string common case와 structured continuation case를 모두 허용할 수 있지만, end-user authorization boundary로 취급하면 안 된다. [Python AgentSession contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1615-L1649) [ADR-0029 lifecycle split](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0029-python-agent-session-identity.md#L243-L267)

### 결정 2. Java in-memory store는 branch-safe snapshot semantics를 기본값으로 둔다

Python `SessionStore`의 deepcopy-on-set/get semantics는 concurrent continuation이나 branch-like replay가 저장본을 오염시키지 않는 장점이 있다. Java도 `get()`이 live reference를 반환하지 않는 것이 안전하다. [Python SessionStore deepcopy semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1724-L1754) [Deepcopy tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_sessions.py#L868-L894)

### 결정 3. Java durable snapshot은 typed envelope + explicit version을 강제한다

`.NET` plain object round-trip보다 Python `_SessionSnapshot`의 `{type, version, session_id, service_session_id, state}` envelope가 migration/validation에 유리하다. Java는 JSON default에 explicit `type`/`version` header를 넣고 optional binary codec을 덧붙이는 쪽이 낫다. [Python snapshot envelope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L473-L493) [ADR-0034 msgspec envelope decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L234-L266) [.NET plain session object round-trip](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentSession.cs#L67-L89)

### 결정 4. Java custom session state는 stable type-id registry로 복원한다

Java도 default JSON mapper만으로는 provider-owned custom state를 cold-start 복원하기 어렵다. explicit codec registry, collision rejection, default `toMap/fromMap`-style codec, `Message` 같은 framework-owned known type 선등록이 필요하다. [Python registry rules](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335) [Python Message pre-registration](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L496-L497)

### 결정 5. Java corrupt-snapshot recovery는 parse corruption만 quarantine하고 schema/version mismatch는 보존한다

Python의 selective quarantine 정책은 operationally 균형이 좋다. bytes 자체가 망가졌을 때만 quarantine하고, schema/version/decoder failure는 원본을 남겨 rollback이나 compatible reader를 허용한다. Java도 같은 구분을 따르는 편이 좋다. [Python quarantine branch](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1851-L1871) [Python preserve-on-version/schema/decoder-failure](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1872-L1889) [ADR-0034 quarantine decision](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0034-python-session-store-serialization.md#L276-L279)

### 결정 6. Java hosted persistence는 service continuation과 tenant boundary를 분리한다

hosted multi-tenant Java layer는 `.NET` Foundry처럼 write-once hosted identity context와 physical path partition을 별도로 가져야 한다. `serviceSessionId`는 continuation이고, tenant boundary는 hosted `userId`/agent partition이 맡아야 한다. [HostedSessionContext write-once/read-only](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedSessionContextExtensions.cs#L15-L80) [Foundry path partition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/FileSystemAgentSessionStore.cs#L234-L310) [ADR-0031 defense-in-depth rationale](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0031-hosted-per-user-session-storage-isolation.md#L14-L39)

### 결정 7. Java agent-specific session subtype는 early compatibility gate를 가져야 한다

`.NET` `ChatClientAgent`가 serialize 전에 session type을 강하게 검사하고, Python generic chat path가 structured `service_session_id`를 early reject하는 이유는 “잘못된 session shape를 remote call까지 끌고 가지 않기 위해서”다. Java도 agent/session compatibility를 run entrypoint에서 즉시 검사해야 한다. [`.NET` session-type gate](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L447-L458) [Python generic-chat continuation gate](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L508-L529)
