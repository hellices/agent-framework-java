# 05-function-tools

This document covers only the **function tool definition/decorator/schema generation**, **argument validation/parsing**, **tool mode/selection**, **invocation configuration/layer/budget**, and **parallel calls and execution result semantics** of the agent core. **Tool approval** and **MCP** belong to separate documents, so only the boundary where they meet these features is described here. The .NET pinned core does not define a first-class `FunctionTool`/`@tool` abstraction the way Python does; it takes external `AITool`/`AIFunction` objects and connects them through `FunctionInvokingChatClient` and the function middleware wrapper. The Python core, by contrast, provides `FunctionTool`, `@tool`, `FunctionInvocationConfiguration`, and `FunctionInvocationLayer` directly, and the core owns schema inference and invocation result normalization as well. [FunctionInvocationDelegatingAgent.cs#L30-L68](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgent.cs#L30-L68) [ChatClientAgent.cs#L82-L92](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L82-L92) [_tools.py#L252-L419](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L252-L419) [_tools.py#L1326-L1403](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1326-L1403) [_tools.py#L2845-L2868](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L2845-L2868)

## Purpose

The purpose of this feature is to handle the functions a model can call in the form of a **tool definition plus an input schema plus execution rules plus result normalization**. The Python core builds a JSON schema from the function signature or an explicit schema, validates the input at call time, and normalizes the result into a `list[Content]`. The .NET core concentrates on connecting already-built `AITool`/`AIFunction` objects to the agent lifecycle and on inserting function middleware when needed. [ _tools.py#L310-L419](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L310-L419) [_tools.py#L810-L897](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L810-L897) [FunctionInvocationDelegatingAgentBuilderExtensions.cs#L17-L51](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgentBuilderExtensions.cs#L17-L51)

## Function tool definition / decorator / schema generation

### Python

- When `FunctionTool` has no explicit `input_model`, `_resolve_input_model()` reads the function signature and synthesizes the input model with Pydantic `create_model()`. `self`/`cls`, the context parameter, and `*args`/`**kwargs` are excluded from the schema at that point. [_tools.py#L493-L523](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L493-L523)
- Context injection is handled by `_discover_injected_parameters()` and `_is_context_parameter()`. When the type hint includes `FunctionInvocationContext` that parameter is injected at runtime, and when an explicit input model is present the unannotated name `ctx` is also recognized as a special case. [_tools.py#L420-L445](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L420-L445)
- `parameters()` caches and returns the lazily generated JSON schema. `_input_schema` uses an explicit JSON schema dict as is, and uses the `model_json_schema()` result for an explicit/inferred Pydantic model. [_tools.py#L797-L819](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L797-L819)
- The documentation of the `tool()` decorator states that an explicit `schema` may be a Pydantic `BaseModel` or a JSON schema dict, that a dict schema must be a flat object schema with `properties`, and that complex JSON Schema features such as `oneOf`, `$ref`, and nested composition are not supported. [_tools.py#L1174-L1205](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1174-L1205)
- The pinned tests verify signature inference, an explicit Pydantic schema, an explicit JSON schema dict, and the preservation of custom schema extension fields. [test_tools.py#L33-L68](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L33-L68) [test_tools.py#L71-L89](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L71-L89) [test_tools.py#L92-L128](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L92-L128) [test_tools.py#L245-L269](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L245-L269) [test_tools.py#L288-L303](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L288-L303)

## Argument validation / parsing

### Python

- `FunctionTool.invoke()` immediately rejects a declaration-only tool and sorts out which path the input arrives through among `arguments`, `context.arguments`, and direct kwargs. Direct kwargs must match the declared tool parameters, and runtime data must be passed only through `FunctionInvocationContext`. [_tools.py#L586-L649](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L586-L649)
- On the inferred or explicit Pydantic model path it uses `model_validate(...).model_dump(exclude_unset=True)`. Explicitly supplied nulls are kept and only values the model omitted are removed, so the function's Python defaults apply. [_tools.py#L655-L690](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L655-L690)
- On the explicit JSON schema dict path, `_validate_arguments_against_schema()` performs a lightweight check of required fields, `additionalProperties: false`, enum membership, and scalar type/list-of-types. [_tools.py#L1079-L1126](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1079-L1126)
- When the model sends the function call payload as a JSON string, `Content.parse_arguments()` first distinguishes object from non-object and converts it into a dict or `{"raw": ...}`. That parsing is an upstream stage of the function tool invocation layer. [_types.py#L1612-L1652](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L1612-L1652)
- The pinned tests verify explicit schema tool invocation, that the same argument validation applies even on the `skip_parsing=True` path, and that unexpected runtime kwargs are rejected. [test_tools.py#L272-L285](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L272-L285) [test_tools.py#L1468-L1487](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_tools.py#L1468-L1487)

### .NET

- The pinned core source has no Python-style function argument schema generation/validation. The function middleware wrapper puts the already prepared `AIFunctionArguments` into the ambient `FunctionInvocationContext` or a new context and passes it to `AIFunction.InvokeCoreAsync()`. [FunctionInvocationDelegatingAgent.cs#L70-L87](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgent.cs#L70-L87)

## Invocation configuration / layers / budgets

### Python

- `normalize_function_invocation_configuration()` supplies the defaults `enabled=True`, `max_iterations=DEFAULT_MAX_ITERATIONS`, `max_function_calls=None`, `max_consecutive_errors_per_request=DEFAULT_MAX_CONSECUTIVE_ERRORS_PER_REQUEST`, `terminate_on_unknown_calls=False`, `additional_tools=[]`, and `include_detailed_errors=False`, and validates the numeric constraints. [_tools.py#L1383-L1403](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1383-L1403)
- `max_iterations` limits the number of LLM round trips, and `max_function_calls` limits the total number of function executions, but it is a **best-effort budget that is checked after a batch has executed**. [ _tools.py#L1332-L1360](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1332-L1360)
- `FunctionInvocationLayer` sorts out the runtime middleware, prepares the run-local mutable options/tool list, and then branches to the non-streaming `_get_response_with_function_invocation()` or the streaming `_stream_response_with_function_invocation()`. [_tools.py#L3238-L3335](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L3238-L3335)
- The non-streaming loop is a three-stage structure: an approval pre-phase → a model/execution alternating phase → a tools-disabled final phase once the iteration budget is exhausted. Between every phase, `budget_state["attempt_count"]`, `budget_state["total_function_calls"]`, and `options["tool_choice"]` are updated. [_tools.py#L2885-L3015](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L2885-L3015)
- `_disable_tools_at_function_call_limit()` blocks further tool execution by setting `options["tool_choice"] = "none"` when the limit is reached, and `_reset_required_tool_choice()` releases the `"required"` selection mode after one iteration. [_tools.py#L2583-L2612](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L2583-L2612)

## Parallel calls and execution result semantics

### Python

- `_try_execute_function_call_groups()` first classifies control-flow conditions such as approval/declaration-only/unknown-call termination, and executes only the fully executable batch in parallel. [ _tools.py#L1735-L1828](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1735-L1828)
- Parallel execution creates a task per function call with `contextvars.copy_context().run(asyncio.create_task, ...)` and collects the results with `asyncio.gather()`. The results are preserved as an **ordered group list in the same order as the input function calls**. [_tools.py#L1829-L1850](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1829-L1850)
- The return shape of `_execute_single_function_call()` is `(list[Content], terminate_flag)`.  
  - On normal execution it becomes `[Content.from_function_result(...)]` or the content group returned by middleware.  
  - On `MiddlewareTermination` the terminate flag can become `True`.  
  - On `UserInputRequiredException` the contents carried by the exception are propagated as is after being augmented with `call_id`/`id`. When there are no details, a synthetic function_result error is created. [_tools.py#L1649-L1707](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1649-L1707)
- `_FunctionExecutionBatch` keeps `result_groups`, provides a flatten view through the `contents` property, and decides `had_errors` from the presence of a `function_result.exception`. [_tools.py#L1853-L1874](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1853-L1874)
- `FunctionTool.parse_result()` normalizes the raw return value into a `list[Content]`: `None → [""]`, `str → text`, `Content → [Content]`, `list[Content|other] → content list`, and an arbitrary object → JSON text. [_tools.py#L842-L883](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L842-L883)

- The Python `FunctionTool.invoke()` is an async public API, but a sync function runs by default outside the event loop with `asyncio.to_thread()`. ## Java decisions

- Java is better off having a **first-class `FunctionTool` abstraction** closer to Python than to .NET. Only then can the core consistently own schema generation, declaration-only tools, per-instance counters, and the raw-versus-parsed result semantics. [ _tools.py#L310-L419](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L310-L419) [_tools.py#L842-L897](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L842-L897)
- As a concrete design, in Java it is better to split `FunctionTool` into an immutable definition plus mutable runtime counters. Accumulating `invocation_count` on one object as Python does creates cross-request state when a singleton tool is reused, so Java must separate the definition from the runtime state or make a scoped copy easy to create. [_tools.py#L334-L349](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L334-L349) [_tools.py#L407-L418](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L407-L418)
- For the selection semantics it is better to have an explicit object model like Python's `ToolMode`. Representing `"required"` and `"required_function_name"` as separate state makes the provider-neutral contract sharper. [_types.py#L3640-L3651](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3640-L3651) [_types.py#L3876-L3914](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3876-L3914)
- For the invocation budget, `max_iterations` and `max_function_calls` should be separated as in Python, but the best-effort semantics of checking after a parallel batch has executed must be stated in the API documentation. Hiding it makes the operational budget/cost expectation diverge from reality. [_tools.py#L1332-L1360](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1332-L1360) [test_function_invocation_logic.py#L1686-L1735](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_function_invocation_logic.py#L1686-L1735)
- Approval and MCP should be separated into their own subsystems, and the function tool core should have only the narrow seam where it meets them. Keeping just `approvalMode`, `kind`, and an external tool expansion hook in the core type, for example, is appropriate. [_tools.py#L315-L333](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L315-L333) [_types.py#L3825-L3873](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3825-L3873)
