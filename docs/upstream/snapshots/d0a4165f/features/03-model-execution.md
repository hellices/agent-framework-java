# 03-model-execution

This document covers only the **model client connection**, **capability contract**, **request options**, **sync/async execution paths**, **streaming/continuation**, **cancellation**, and **response assembly** of the agent core. On the .NET side the centre is `ChatClientAgent`, which wraps `IChatClient`, together with its option/decorator chain; on the Python side the centre is the `SupportsChatGetResponse` protocol, `BaseChatClient`, and the `RawAgent`/`Agent` path that connects them to the agent. ## Purpose

The purpose of this feature is to provide a **provider-neutral execution seam** so that the agent core can handle “model invocation” consistently. In .NET, `ChatClientAgent` turns the `IChatClient` call into the integration point for lifecycle/session/provider, while in Python `SupportsChatGetResponse.get_response()` is the common contract of every chat model client and `BaseChatClient` then takes charge of option validation, compaction, and stream finalization. [ChatClientAgent.cs#L39-L40](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L39-L40) [_clients.py#L85-L200](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L85-L200) [_clients.py#L443-L558](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L443-L558)

## Model client connection / capability contracts

### .NET

- The .NET pinned source scope has no Python-style set of “supports X” protocols. Capability is exposed through the `IChatClient` decoration stack and `GetService()` discovery. For example, `ChatClientAgent` reads `ChatClientMetadata` at construction time to build the provider metadata, and decides whether function invocation middleware is supported by looking for a `FunctionInvokingChatClient` inside the stack. [ChatClientAgent.cs#L122-L131](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L122-L131) [FunctionInvocationDelegatingAgentBuilderExtensions.cs#L33-L49](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgentBuilderExtensions.cs#L33-L49)
- The default connection path is `IChatClient.AsAIAgent()` or `ChatClientBuilder.BuildAIAgent()`. Both ultimately create a `ChatClientAgent`. [ChatClientExtensions.cs#L18-L50](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L18-L50) [ChatClientBuilderExtensions.cs#L15-L87](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientBuilderExtensions.cs#L15-L87)
- When `UseProvidedChatClientAsIs=false` the framework injects the default decorator stack. That stack composes approval binding, the approval-not-required bypass, the optional invocable bypass, `FunctionInvokingChatClient`, optional message injection, optional per-service-call persistence, and the deferred OpenTelemetry slot. [ChatClientExtensions.cs#L52-L140](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L52-L140)

- Python's core capability contract is `SupportsChatGetResponse`. It expresses “a sequence of `Message` in, a complete `ChatResponse` or a streaming `ResponseStream` out” as a structural protocol. ## Request Options

### .NET

- The base `AgentRunOptions` provides `ContinuationToken`, `AllowBackgroundResponses`, `AdditionalProperties`, and `ResponseFormat`. Continuation and background are optional, and an implementation that does not support them may ignore them. [AgentRunOptions.cs#L19-L127](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRunOptions.cs#L19-L127)
- `ChatClientAgentRunOptions` goes further and provides per-run `ChatOptions` and a `ChatClientFactory`. [ChatClientAgentRunOptions.cs#L15-L67](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentRunOptions.cs#L15-L67)
- `ChatClientAgent.CreateConfiguredChatOptions()` merges the agent-level default `ChatOptions` with the request-level `ChatOptions`. Scalars take the request first, instructions are newline concatenated, additional properties are overwritten request-first, stop sequences and tools are concatenated, and `ResponseFormat`/`AllowBackgroundResponses`/`ContinuationToken`/`AdditionalProperties` apply the last override from `AgentRunOptions`. [ChatClientAgent.cs#L541-L688](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L541-L688)

### Python

- The Python `ChatOptions` defines the provider-neutral common denominator: `model`, `temperature`, `top_p`, `max_tokens`, `stop`, `seed`, `logit_bias`, `frequency_penalty`, `presence_penalty`, `tools`, `tool_choice`, `allow_multiple_tool_calls`, `response_format`, `metadata`, `user`, `store`, `conversation_id`, and `instructions`. ## Detailed execution flow

### .NET non-streaming path

1. `ChatClientAgent.RunCoreAsync()` materializes the input messages. [ChatClientAgent.cs#L205-L212](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L205-L212)  
2. `PrepareSessionAndMessagesAsync()` prepares the session/chat options/messages/continuation token. Background/continuation validation, session compatibility, the conversation id conflict check, and the history/context provider merge all happen here. [ChatClientAgent.cs#L699-L807](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L699-L807)  
3. `ApplyRunOptionsTransformations()` transforms the original client when a per-run `ChatClientFactory` is present. [ChatClientAgent.cs#L266-L288](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L266-L288)  
4. The actual model call descends to `chatClient.GetResponseAsync(...)`. On failure it sends a provider failure notification and rethrows the exception. On success it reflects the response's conversation id into the session, fills in the `AuthorName` of the response messages, and wraps the result as an `AgentResponse` after the provider success notification. [ChatClientAgent.cs#L223-L264](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L223-L264)

### .NET streaming path

1. Streaming goes through `PrepareSessionAndMessagesAsync()` and `ApplyRunOptionsTransformations()` in the same way. [ChatClientAgent.cs#L291-L317](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L291-L317)  
2. It grabs the enumerator of `GetStreamingResponseAsync(...)` directly and wraps everything from the first `MoveNextAsync()` in try/catch, sending a provider failure notification on an exception. [ChatClientAgent.cs#L321-L352](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L321-L352)  
3. On every update it corrects the `AuthorName`, stores it in the local `responseUpdates` buffer, and `yield`s to the host an `AgentResponseUpdate` carrying the wrapped continuation token. [ChatClientAgent.cs#L354-L367](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L354-L367)  
4. After the stream ends it turns the buffered `ChatResponseUpdate` list into a complete response with `ToChatResponse()` and finishes the conversation id and the provider notifications. [ChatClientAgent.cs#L385-L401](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L385-L401)

### Python direct client path

1. `BaseChatClient.get_response()` first looks at whether a compaction/tokenizer override is present. Without an override it descends directly to `_inner_get_response()`; with one it calls it after `_prepare_messages_for_model_call()`. [_clients.py#L510-L558](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L510-L558)
2. When streaming it wraps the result of `_inner_get_response(..., stream=True)` with `ResponseStream.from_awaitable()`, and when non-streaming it returns the coroutine as is. [_clients.py#L524-L558](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L524-L558)
3. A provider subclass must implement `_inner_get_response(messages, stream, options, **kwargs)`, and is expected to call `_validate_options()` at the start. [_clients.py#L415-L439](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L415-L439) [_clients.py#L329-L340](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L329-L340)

### Python agent→client handoff path

- `RawAgent._call_chat_client()` passes the already prepared `session_messages`, the merged `chat_options`, the compaction/tokenizer overrides, `function_invocation_kwargs`, and `client_kwargs` straight to the client contract. The final seam between agent execution and direct client execution is therefore the single `SupportsChatGetResponse.get_response()`. [_agents.py#L1119-L1161](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1119-L1161)

## State and persistence

- .NET model execution treats the presence of a `ConversationId` as meaning that service-managed history is in use, and tries not to let it conflict with a local `ChatHistoryProvider`. `ResolveChatHistoryProvider()` disengages the local provider when `chatOptions.ConversationId` or `session.ConversationId` is present. [ChatClientAgent.cs#L983-L1029](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L983-L1029)
- In .NET background/continuation resumption, `ChatClientAgentContinuationToken` keeps, in addition to the inner provider continuation token, the previous input messages and the updates already received, so that enough context can be restored to the session/history/provider on resume. [ChatClientAgent.cs#L1054-L1091](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L1054-L1091)
- In Python the client-level capability `STORES_BY_DEFAULT` is the storage ownership hint for model execution. When it is `True` the agent does not auto-inject a local `InMemoryHistoryProvider`, and switches to the local history path only when `store=False` is stated explicitly. [_clients.py#L279-L286](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L279-L286) [_agents.py#L1341-L1368](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1341-L1368)

## Concurrency, streaming, and cancellation

- .NET uses an explicit `CancellationToken` at both the agent level and the chat-client level. The same token is passed to `IChatClient.GetResponseAsync()`/`GetStreamingResponseAsync()`. ## Response Assembly

### .NET

- Non-streaming assembly is a thin wrapper that wraps the underlying `ChatResponse` in `new AgentResponse(chatResponse)`. Because `ChatResponse` is already a complete object, there is almost no extra assembly logic. [AgentResponse.cs#L48-L70](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L48-L70) [ChatClientAgent.cs#L259-L264](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L259-L264)
- Streaming assembly is two stages: converting the buffered `ChatResponseUpdate` list into a final `ChatResponse` and then promoting it to a wrapper `AgentResponse`. Each host-facing `AgentResponseUpdate` wraps the provider update as is, but the final response is assembled once more at stream end. [ChatClientAgent.cs#L317-L401](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L317-L401) [AgentResponseUpdate.cs#L63-L79](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponseUpdate.cs#L63-L79)

### Python

- `BaseChatClient._build_response_stream()` binds the stream source and the finalizer to create a `ResponseStream`. The default finalizer is `_finalize_response_updates()`, which in turn calls `ChatResponse.from_updates()`. [_clients.py#L342-L364](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L342-L364)
- `ChatResponse.from_updates()` assembles the final response through `_process_update()` and `_finalize_response()`. Even when the provider does not hand over a complete response directly, the core can therefore reconstruct the final response from the update sequence alone. [_types.py#L2370-L2405](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2370-L2405) [_types.py#L2140-L2146](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2140-L2146)

## Java decisions

- Java is better off first establishing **explicit client capability contract interfaces** as Python does. Separating a base `ChatClient` contract from detailed capability interfaces such as `SupportsCodeInterpreter` and `SupportsWebSearch` gives high compile-time discoverability. That fits the Java IDE and type system better than .NET's decoration/service-discovery approach. [_clients.py#L85-L200](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L85-L200) [_clients.py#L667-L846](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L667-L846)
- At the same time a per-run client transformation seam like .NET's `ChatClientFactory` is very useful in Java too. A hybrid that keeps **typed capability interfaces plus a per-request client decorator factory** is therefore appropriate for Java. [ChatClientAgentRunOptions.cs#L55-L67](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentRunOptions.cs#L55-L67) [ChatClientAgentRunOptionsTests.cs#L51-L90](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.UnitTests/ChatClient/ChatClientAgentRunOptionsTests.cs#L51-L90)
- For request options it is safer to make the provider-neutral common keys the primary contract as Python does, and to separate provider-specific options into a dedicated typed extension object or a namespaced map. Reflecting both .NET's rich `ChatOptions` merge semantics and Python's `validate_chat_options()` constraints lets the Java core design the option precedence and validation layers clearly as well. [ChatClientAgent.cs#L541-L688](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L541-L688) [_types.py#L3660-L3787](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3660-L3787)
- For cancellation, including an explicit token/handle in the public contract as .NET does suits Java better. Python-style implicit asyncio cancellation is not standard in Java. [ChatClientAgent.cs#L205-L401](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L205-L401) [_clients.py#L171-L200](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L171-L200)
