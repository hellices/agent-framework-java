# 02-message-content

This document covers only the **Message/Role/Content types**, **multimodal content**, **response/update/usage/finish reason**, **normalization**, and the **message-content-stream model** of the agent core. Within that scope the .NET core does not define new Message/Content types of its own; it works around `AgentResponse`/`AgentResponseUpdate`, which wrap `ChatMessage`, `ChatRole`, `AIContent`, `ChatResponse`, and `ChatResponseUpdate` from `Microsoft.Extensions.AI`. The Python core, by contrast, defines `Content`, `Message`, `ChatResponse`, `ChatResponseUpdate`, `AgentResponse`, `AgentResponseUpdate`, and `ResponseStream` directly. [AgentResponse.cs#L1-L10](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L1-L10) [AgentResponseUpdate.cs#L1-L10](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponseUpdate.cs#L1-L10) [_types.py#L474-L591](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L474-L591) [_types.py#L1751-L1881](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L1751-L1881) [_types.py#L2214-L3050](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2214-L3050)

## Purpose

The purpose of this feature is to express model input and output, tool call traces, usage metadata, and partial streaming chunks in **a consistent conversation data model**. .NET preserves the provider-neutral `AIContent` collection as is and only adds an agent-level response wrapper, while Python puts text, binary, URI, hosted file, code interpreter, image generation, shell, MCP, approval, and OAuth consent all into a single `Content` union model. [AgentResponse.cs#L14-L27](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L14-L27) [AgentResponseUpdate.cs#L14-L33](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponseUpdate.cs#L14-L33) [_types.py#L484-L540](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L484-L540) [_types.py#L964-L1268](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L964-L1268)

## Content model and multimodal representation

### .NET

- The .NET core does not define the `AIContent` subtype hierarchy itself. Instead `AgentResponseUpdate.Text` and `AgentResponse.Text` treat only `TextContent` specially and preserve the remaining `AIContent` opaquely. [AgentResponseUpdate.cs#L91-L104](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponseUpdate.cs#L91-L104) [AgentResponse.cs#L131-L143](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L131-L143)
- The internal `AIContentExtensions.ConcatText()` also takes only `TextContent` as a concatenation target. Multimodal payloads are therefore not interpreted at the wrapper level. [AIContentExtensions.cs#L16-L61](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContentExtensions.cs#L16-L61)
- When turning a complete `AgentResponse` back into updates, usage is emitted as a separate update carrying a single `UsageContent`, and the message contents reuse the original `AIContent` list as is. [AgentResponse.cs#L245-L310](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L245-L310)

### Python

- `Content` unifies, inside a single class, the text, reasoning text, data URI, external URI, error, usage, function call/result, hosted file/vector store, code interpreter, image generation, shell, MCP, approval request/response, and OAuth consent request fields. [_types.py#L484-L590](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L484-L590)

[_types.py#L81-L120](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L81-L120) [_types.py#L230-L271](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L230-L271) [_types.py#L649-L779](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L649-L779)

[_types.py#L981-L1268](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L981-L1268)

## Normalization and message assembly

### .NET

## Java decisions

- Java is better off having a **core-owned Message/Content/Response model** as Python does. Exposing external AI SDK types directly on the public core surface as .NET does would make the evolution of core semantics such as the multimodal taxonomy, approval content, hosted assets, and the MCP informational-only rule dependent on an external library. [AIContentExtensions.cs#L16-L61](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContentExtensions.cs#L16-L61) [_types.py#L484-L590](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L484-L590)
- Concretely, in Java it is better for `Message` to take a `role + List<Content>` structure and for `Content` to take a sealed hierarchy or tagged union style. Putting everything into a single tagged class as Python does makes serialization simple, but in Java a sealed interface plus subtype records can be safer. The `additionalProperties` and `rawRepresentation` escape hatches must be kept, however, so that provider-specific metadata is not lost. [_types.py#L538-L551](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L538-L551) [AgentResponse.cs#L219-L240](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse.cs#L219-L240)
- For the stream model, a dual structure that keeps a generic wrapper like Python's `ResponseStream` while also providing update↔response conversion helpers as a separate utility, as .NET does, is appropriate. Only then can streaming and non-streaming consumers share the same message/content model while the finalizer/hook/gate semantics stay explicit. [AgentResponseExtensions.cs#L106-L176](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponseExtensions.cs#L106-L176) [_types.py#L3061-L3515](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3061-L3515)
