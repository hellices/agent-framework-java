# 22. A2A

## 범위

이 문서는 Microsoft Agent Framework의 **A2A(Agent2Agent) 통합과 hosting**을 다룬다. 구체적으로 다음을 포함한다.

- remote A2A agent를 Agent Framework `AIAgent`로 감싸는 **client/agent integration**
- local Agent Framework agent를 A2A 프로토콜로 노출하는 **hosting integration**
- **AgentCard**, **Message**, **Task**, **Artifact**의 의미와 매핑
- streaming, continuation token, poll/subscribe 경계
- session/state와 identity/auth 경계
- .NET / Python 구현 차이
- conformance tests
- Java 설계 결정

반대로 generic hosting lifecycle, store abstraction, workflow checkpoint 일반론은 별도 generic hosting 문서의 범위이며 여기서는 A2A-specific semantics와 hosting 접점만 다룬다. 또한 OpenAI Responses, AG-UI, MCP, Foundry Hosted Agents, Telegram/ChatKit의 상세는 별도 문서 범위다. (출처: [Python A2A README](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/README.md#L9-L28), [Python hosting-a2a README](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/hosting-a2a/README.md#L1-L10), [.NET Hosting.A2A registration docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Hosting.A2A/A2AServerServiceCollectionExtensions.cs#L22-L31))

## 요약

A2A는 이 코드베이스에서 두 층으로 나뉜다. 첫째는 **remote A2A agent를 local `AIAgent`처럼 다루는 client/agent integration**이고, 둘째는 **local Agent Framework target을 A2A protocol endpoint로 노출하는 hosting integration**이다. .NET에서는 `Microsoft.Agents.AI.A2A`가 preview client/agent package이고, `Microsoft.Agents.AI.Hosting.A2A` + `...AspNetCore`가 preview hosting package다. Python에서는 `agent-framework-a2a`가 beta 수준의 full integration package(`A2AAgent`, `A2AExecutor`)이고, `agent-framework-hosting-a2a`는 alpha helper-only package로 app-owned native A2A server composition을 돕는다. 카드(card) 쪽에서는 .NET이 `AgentCard.AsAIAgent(...)`와 `IA2AClient.AsAIAgent(...)`로 discovery path를 나누고, Python helper는 `AgentA2AAdapter`/`WorkflowA2AAdapter`로 public `AgentCard`를 생성한다. Task/Artifact 모델은 두 언어 모두 중요하지만, .NET remote `A2AAgent`는 task를 `AgentResponse`/`AgentResponseUpdate`와 continuation token으로 surface하고, Python `A2AExecutor`는 local agent streaming output을 stable artifact id + append semantics로 A2A task artifact updates에 투영한다. ## 목적

A2A 지원의 목적은 Agent Framework가 **외부 A2A ecosystem과 상호운용**할 수 있게 하는 것이다. 이 목적은 두 방향으로 나뉜다.

1. **Client 방향**: 이미 A2A로 노출된 remote agent를 Agent Framework 안에서 하나의 `AIAgent`처럼 사용한다.
2. **Hosting 방향**: local Agent Framework agent/workflow를 A2A-compliant client가 호출할 수 있도록 A2A server surface로 노출한다.

이때 “A2A integration”은 단순 text chat bridge가 아니라, A2A 고유의 **context**, **task**, **artifact**, **status update**, **input-required continuation** 개념을 Agent Framework의 `AgentSession`, `AgentResponse`, `AgentResponseUpdate`, `ContinuationToken`에 대응시키는 작업을 포함한다. (출처: [.NET A2AAgent summary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/A2AAgent.cs#L18-L25), [Python A2A README A2AAgent section](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/README.md#L9-L24), [Python A2AExecutor section](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/README.md#L25-L48))

## 경계

### 이 기능이 하는 일
- A2A client or card를 Agent Framework `AIAgent`로 변환한다.
- Agent Framework `Message`/`Content`를 A2A `Message`/`Part`로 변환한다.
- A2A `Task`, `Artifact`, `TaskStatusUpdateEvent`, `TaskArtifactUpdateEvent`를 Agent Framework response/update로 변환한다.
- local host에서 A2A task/message lifecycle을 관리하도록 돕는다.
- app-owned native A2A server가 쓸 card generation, mode validation, agent/workflow conversion helper를 제공한다. (출처: [.NET A2AClientExtensions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/Extensions/A2AClientExtensions.cs#L10-L23), [.NET A2AAgentTaskExtensions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/Extensions/A2AAgentTaskExtensions.cs#L9-L59), [Python A2AExecutor summary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/agent_framework_a2a/_a2a_executor.py#L31-L42), [Python hosting-a2a README table](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/hosting-a2a/README.md#L11-L18))

### 이 기능이 하지 않는 일
- A2A entry point의 authentication/authorization
- caller-supplied `contextId`/`taskId`를 trusted store key로 승인하는 정책
- A2A task store durable backend 선택
- non-A2A protocol routing
- generic hosting/session store lifecycle 자체

특히 Python helper package는 “executor, task lifecycle, event queue, task store, routes, session policy, authentication, deployment”를 제공하지 않는다고 명시한다. .NET hosting도 task/session identifiers를 authorization token으로 취급하지 말라고 문서화한다. (출처: [Python hosting-a2a README does not provide lifecycle/routes/auth](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/hosting-a2a/README.md#L6-L10), [.NET hosting trust model](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Hosting.A2A/A2AServerServiceCollectionExtensions.cs#L31-L47), [Python A2A security considerations](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/README.md#L60-L64))

## Tasks / messages / artifacts

## .NET remote agent integration

### Message path
A2A remote response가 `Message`이면 `A2AAgent`는 이를 assistant `ChatMessage`로 변환해 `AgentResponse`를 만든다. response id는 `message.MessageId`이고, metadata는 `AdditionalProperties`로 보존된다. (출처: [.NET ConvertToAgentResponse(Message)](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/A2AAgent.cs#L412-L423))

### Task path
A2A remote response가 `AgentTask`이면 `A2AAgent`는:

- `task.Id`를 response id로 쓰고
- `task.Artifacts`와 `task.Status.GetUserInputRequests()`를 `Messages`/`AIContents`로 변환하며
- task state가 `Submitted` 또는 `Working`이면 continuation token을 만든다
- task state가 `Completed`이면 `FinishReason.Stop`으로 매핑한다

즉 .NET의 remote A2A integration은 이미 **task-aware**다. (출처: [.NET A2AAgentTaskExtensions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/Extensions/A2AAgentTaskExtensions.cs#L12-L59), [.NET ConvertToAgentResponse(AgentTask)](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/A2AAgent.cs#L425-L437), [.NET CreateContinuationToken](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/A2AAgent.cs#L402-L410))

### Artifact path
artifact는 assistant `ChatMessage` 또는 `AIContent` sequence로 flatten된다. metadata와 raw representation도 보존된다. (출처: [.NET A2AArtifactExtensions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.A2A/Extensions/A2AArtifactExtensions.cs#L8-L26))

## Python remote agent integration

Python `A2AAgent`도 A2A stream에서 다음 payload들을 읽는다.

- `message`
- `task`
- `status_update`
- `artifact_update`

`task`/`status_update`/`artifact_update`는 각각 `AgentResponseUpdate`로 풀리고, terminal/no-content case에서는 누적 intermediate updates를 flush하는 로직까지 가진다. 또한 `artifact_update`는 항상 yield되어 파일/바이너리 등 실질 콘텐츠가 유실되지 않게 한다. (출처: [Python _map_a2a_stream main loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/agent_framework_a2a/_agent.py#L565-L666), [Python _updates_from_task loop consumers](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/agent_framework_a2a/_agent.py#L593-L663))

## .NET hosting

`.NET` hosting handler는 A2A response를 두 가지로 나눈다.

- continuation token이 없으면 lightweight `Message` response
- continuation token이 있으면 `TaskUpdater.SubmitAsync` / `StartWorkAsync` 등 **task lifecycle**로 surface

그리고 resumed/update path에서는 완료 시 artifact를 추가하고 task를 complete 한다. 즉 hosting layer는 A2A의 “message vs task” duality를 직접 책임진다. (출처: [.NET A2AAgentHandler HandleNewMessageAsync](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Hosting.A2A/A2AAgentHandler.cs#L74-L127), [.NET HandleTaskUpdateAsync completion/progress](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Hosting.A2A/A2AAgentHandler.cs#L160-L213))

## Python hosting

Python `A2AExecutor`는 local agent output을 A2A protocol event로 투영한다.

- non-streaming final `Message`는 `TaskStatusUpdateEvent`-style working status message
- streaming `AgentResponseUpdate`는 `add_artifact(...)`로 `TaskArtifactUpdateEvent`
- 같은 response stream의 chunk들은 **stable artifact id**를 공유하고, 이후 chunk에는 `append=True`를 준다
- intermediate `function_call`/`function_result` 같은 tool-use internal content는 user-facing A2A part로 surface하지 않고 조용히 skip한다

이 마지막 점이 “tool integration” 경계다. 즉 A2A host는 internal tool loop를 그대로 노출하지 않고, A2A가 이해할 수 있는 최종 text/data/uri output만 전송한다. (출처: [Python A2AExecutor _run_stream stable artifact id](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/agent_framework_a2a/_a2a_executor.py#L184-L201), [Python A2AExecutor handle_events mapping](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/agent_framework_a2a/_a2a_executor.py#L214-L306), [Python test append semantics](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/tests/test_a2a_executor.py#L823-L843), [Python test skipping intermediate tool content](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/a2a/tests/test_a2a_executor.py#L861-L876))

## Acceptance scenarios

1. **Remote agent as local agent**
   - direct-configured A2A client 또는 discovered `AgentCard`로 remote agent를 `AIAgent`처럼 호출할 수 있어야 한다.
   - response가 immediate message면 assistant message로, task면 task-derived response/continuation token으로 바뀌어야 한다.

2. **Task continuation**
   - in-progress task는 continuation token을 surface해야 한다.
   - terminal task resubscribe가 unsupported면 fallback polling path가 있어야 한다.
   - continuation token을 쓸 때 새 user messages를 동시에 받으면 reject해야 한다.

3. **Message/task linking**
   - session이 `INPUT_REQUIRED` task state를 가리키면 outbound A2A message는 `task_id`로 같은 task를 이어야 한다.
   - 그렇지 않으면 `reference_task_ids`로 follow-up refinement를 표현해야 한다.

4. **Cards**
   - app-owned A2A host는 public `AgentCard`를 생성/게시할 수 있어야 한다.
   - supported interfaces, capabilities, modes, skills를 explicit하게 조정할 수 있어야 한다.

5. **Artifacts**
   - streaming host는 같은 logical response의 chunk들을 같은 artifact id로 묶고 append semantics를 제공해야 한다.
   - file/data/uri outputs는 artifact/message update로 손실 없이 전달돼야 한다.

6. **Identity boundary**
   - `contextId`, `taskId`, session/thread ids는 routing handle이지 bearer credential이 아니어야 한다.
   - multi-user host는 principal/tenant dimension을 별도로 합성해야 한다.

7. **Tool integration boundary**
   - host는 internal tool-use intermediate frames를 그대로 A2A wire로 내보내지 않고, A2A가 이해 가능한 final user-facing output만 surface할 수 있어야 한다.

## 결론

A2A는 이 저장소에서 단순 “외부 chat protocol 하나 더”가 아니라, **task-bearing agent protocol**로 구현되어 있다. remote agent integration에서는 task/continuation과 artifacts가 핵심이고, hosting integration에서는 message와 task lifecycle을 언제 어떤 기준으로 surface할지, 그리고 그 identifiers를 어떻게 principal-scoped state로 연결할지가 핵심이다. Java 구현도 이 구조를 따라 **remote A2A agent wrapper**, **A2A hosting helper**, **framework-specific binder**를 분리하고, 카드/stream/task/artifact 모델을 first-class 개념으로 유지하는 편이 가장 자연스럽다.
