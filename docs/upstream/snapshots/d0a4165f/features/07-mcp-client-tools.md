# 07-mcp-client-tools

This document covers only the **MCP client tools** of the Agent Framework. The scope is the Python core's `MCPStdioTool` / `MCPStreamableHTTPTool` / `MCPWebsocketTool`, their **client lifecycle**, **tool discovery / invocation**, the **prompts / resources boundary**, the **sampling approval callback**, the handling of **MCP long-running tasks (SEP-2663)**, and **trace / error / cancellation / security**; on the reviewed .NET side the focus is not a transport-specific tool surface but a **long-running task wrapper that exposes an existing `McpClient` as an agent tool**. The **MCP hosting/server implementation** belongs to a separate document. ## Purpose

The purpose of this feature is to connect an external MCP server as a **tool/prompt surface the agent can call**, and to wrap the transport differences (stdio / HTTP / WebSocket), discovery, sampling, the long-running task lifecycle, and the security guardrails. In Python the `MCPTool` base unifies connection management, discovery, tool invocation, prompt invocation, the sampling callback, and long-running tasks, and the transport subclasses specialize only the creation of each transport client. The reviewed .NET package exposes the result of `McpClient.ListToolsAsync()` as `AIFunction` objects and hides long-running tasks inside the agent tool loop by wrapping only task-capable tools in `TaskAwareMcpClientAIFunction`. [_mcp.py#L396-L412](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L396-L412) [_mcp.py#L414-L559](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L414-L559) [McpClientTaskExtensions.cs#L19-L33](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Mcp/McpClientTaskExtensions.cs#L19-L33) [TaskAwareMcpClientAIFunction.cs#L22-L39](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Mcp/TaskAwareMcpClientAIFunction.cs#L22-L39)

## Client lifecycle

### Python

- `MCPTool.connect(reset=False)` serializes connects through a lifecycle owner task / queue model. Even when an external caller connects directly, the actual connect/close is performed on the owner task. [_mcp.py#L1124-L1210](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1124-L1210) [_mcp.py#L1271-L1279](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1271-L1279)

## Tool discovery / invocation

### Python discovery

- `load_tools()` walks the server `tools/list` with pagination and converts each remote tool into a local `FunctionTool`. For a zero-arg object tool the input schema is supplemented with `{}` when there are no `properties`. [_mcp.py#L1785-L1933](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1785-L1933)
- `tool_name_prefix` prefixes the local name, but allowlist/approval matching is performed against a safe candidate set of the raw remote name and the normalized/local name. [_mcp.py#L188-L205](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L188-L205) [_mcp.py#L874-L885](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L874-L885)
- Remote name normalization collisions are not allowed. When another remote tool maps to the same local name, a `ToolExecutionException` is raised. [_mcp.py#L1874-L1885](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1874-L1885)

## Sampling approval callback

### Python

- The reviewed Python core source explains the MCP transport, discovery, sampling, task lifecycle, and header security in great detail, but the public README scope does not explain the whole behavior model of MCP client tools this deeply. The actual semantics become visible only when the source and the tests are read together. ## Java decisions

- Java is better off providing a **transport-specific MCP client tool abstraction** directly as Python does. Because the connection lifecycle, security, and discovery semantics of stdio / HTTP / WebSocket differ considerably, transport-aware subclasses are clearer than a single generic wrapper. [_mcp.py#L2705-L3399](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L2705-L3399)
- At the same time it is useful to have a separate **low-level adapter that exposes an already connected MCP client as an agent tool list**, as in the reviewed .NET. A hybrid where Java has both high-level transport classes and a low-level `ConnectedMcpClientAdapter` is therefore appropriate. [McpClientTaskExtensions.cs#L17-L60](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Mcp/McpClientTaskExtensions.cs#L17-L60)
- For sampling, **default deny plus an explicit approval callback** as in Python is desirable. Because an external MCP server is an untrusted third party, allowing server-initiated prompt forwarding by default increases the confused-deputy risk. [_mcp.py#L130-L145](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L130-L145) [_mcp.py#L1456-L1468](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1456-L1468)
- For long-running tasks it is better, as in both Python and .NET, to have a separate option object and to take **local cancellation → best-effort remote cancel**, **deadline → abandonment plus cancel**, and **no re-issuing of tools/call once the task id is known after create** as the core invariants. [_mcp.py#L2220-L2223](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L2220-L2223) [_mcp.py#L2263-L2285](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L2263-L2285) [TaskAwareMcpClientAIFunction.cs#L123-L145](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Mcp/TaskAwareMcpClientAIFunction.cs#L123-L145)
- For resources and prompts it is appropriate to separate **prompts as a function-like surface** and resources as a **payload / skill-resource boundary**, as in Python. Exposing resources like tools widens the discovery/model prompt surface excessively. [_mcp.py#L1692-L1784](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_mcp.py#L1692-L1784) [AgentMcpSkill.cs#L18-L26](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Mcp/Skills/AgentMcpSkill.cs#L18-L26)
