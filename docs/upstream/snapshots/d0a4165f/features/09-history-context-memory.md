# 09-history-context-memory

이 문서는 snapshot `d0a4165f`의 **history/context/memory surface**만 다룬다. Python 쪽의 `SessionContext`/`ContextProvider`/`HistoryProvider`/`InMemoryHistoryProvider`/`FileHistoryProvider`와 message injection, per-service-call history persistence, provider memory 경계를 중심으로 설명하고, `.NET` 쪽은 동일 문제를 `ChatHistoryProvider`/`AIContextProvider`/`MessageAIContextProvider`/`MessageInjectingChatClient`/`PerServiceCallChatHistoryPersistingChatClient`로 어떻게 나누는지 비교한다. session snapshot schema와 durable session serialization은 [08-sessions](./08-sessions.md), compaction 정책과 `_excluded` marker의 소유권은 [11-compaction](./11-compaction.md), harness file memory / structured memory는 [12-harness](./12-harness.md) 범위다. [Python session/context/history runtime](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L2339) [.NET history/context abstractions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L15-L350) [.NET message injection / per-call persistence](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L14-L391)

## 상태/목적

- Python의 중심 abstraction은 `agent.run()`마다 새로 생성되는 `SessionContext`이며, provider는 여기에 messages / instructions / tools / middleware를 추가하고 run 뒤에는 `context.response`를 읽는다. `SessionContext`는 `session_id`, `service_session_id`, `input_messages`, ordered `context_messages`, ordered `middleware`, `options`, `metadata`를 모두 들고 있다. [SessionContext fields and lifecycle](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L560)
- Python `ContextProvider`의 목적은 “pre-run injection + post-run extraction”을 하나의 hooks pattern으로 통합하는 것이다. provider-scoped `state`는 항상 `AgentSession.state[source_id]`에 놓이며, provider 인스턴스는 session-specific state를 자기 필드에 보관하지 않는 설계다. [ContextProvider contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L736-L806)
- Python `HistoryProvider`는 `ContextProvider`의 하위 타입으로 conversation history load/store를 담당한다. 한 타입으로 primary memory, audit/logging, evaluation sink를 모두 커버하며, `load_messages`, `store_inputs`, `store_context_messages`, `store_context_from`, `store_outputs` 조합으로 역할을 바꾼다. [HistoryProvider purpose and flags](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L936)
- `.NET`은 같은 관심사를 하나의 `SessionContext`에 모으지 않고, persistent history는 `ChatHistoryProvider`, transient context는 `AIContextProvider`/`MessageAIContextProvider`, loop-level message injection은 `MessageInjectingChatClient`, per-service-call consistency는 `PerServiceCallChatHistoryPersistingChatClient`로 분리한다. [ChatHistoryProvider role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L15-L50) [AIContextProvider role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L15-L41) [MessageInjectingChatClient role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L14-L40)

## 경계

- 이 문서는 **session identity / durable snapshot format / session store**를 직접 설명하지 않는다. history/context provider는 `AgentSession.state` 또는 `.NET` `AgentSession.StateBag`에 의존하지만 snapshot envelope, versioning, quarantine, hosted session routing은 [08-sessions](./08-sessions.md) 범위다. Python source도 provider custom state가 persisted session에 들어갈 때 `register_state_type()` 등록이 필요하다고만 경계를 선언한다. [HistoryProvider state-registration boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L891-L900) [.NET provider session-state helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ProviderSessionState%7BTState%7D.cs#L9-L25)
- compaction은 이 문서의 주제가 아니다. 다만 history load 쪽에서 `_excluded` marker를 무시할지 여부만 `InMemoryHistoryProvider.skip_excluded`와 `FileHistoryProvider.skip_excluded`가 노출한다. compaction rule, exclusion authoring, reducer ownership은 [11-compaction](./11-compaction.md)로 넘긴다. [InMemoryHistoryProvider skip_excluded](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2001-L2048) [FileHistoryProvider skip_excluded](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2097-L2199)
- harness의 file memory / advanced structured memory는 이 문서에서 “core context provider seam을 소비하는 상위 기능”으로만 본다. 실제 file-memory namespace, transcript extraction, topic memory는 [12-harness](./12-harness.md) 범위다. core에서는 `SessionContext.extend_messages(...)`, `extend_tools(...)`, `extend_middleware(...)`가 그런 상위 provider가 붙는 공통 seam이다. [SessionContext extension seams](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L567-L699)
- provider memory(Mem0 / Cosmos / Foundry 등)의 공통 경계는 “**session state를 identity source로 쓰지 않고**, provider-scoped state와 explicit scope를 이용해 외부 memory store를 읽고, 결과는 model에 **untrusted context message**로 넣고, run 뒤에는 input/response에서 memory를 추출해 외부 store를 갱신한다”는 점이다. [Mem0 explicit storage vs retrieval scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/mem0/agent_framework_mem0/_context_provider.py#L44-L62) [CosmosMemory untrusted user-summary injection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L382-L413) [FoundryMemory stores and retrieves via AIContextProvider](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry/Memory/FoundryMemoryProvider.cs#L22-L31)

[HistoryProvider abstract methods](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L938-L1012) [approval-control filter](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L814-L876)

## 실행 흐름

### Python: provider pipeline

1. `RawAgent.run()` 준비 단계는 service storage 여부와 `conversation_id`를 해석한 뒤, **session이 있고 load-enabled history provider가 없고** service-managed conversation 흔적도 없을 때만 `InMemoryHistoryProvider`를 자동 추가한다. [auto-inject in-memory history](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1348-L1368)
2. `SessionContext`는 provider session의 ids와 input messages로 생성된다. `before_run`은 forward order로 호출되며, per-service-call history persistence가 활성화된 경우 `HistoryProvider`는 once-per-run path에서 건너뛰고, `load_messages=False` provider도 건너뛴다. [SessionContext construction and before_run order](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1567-L1600)
3. run 끝에서 framework가 full `AgentResponse`를 `session_context._response`에 꽂은 뒤 `after_run`을 reverse order로 호출한다. per-service-call persistence가 history provider를 이미 소유한 경우 once-per-run `after_run`에서는 그 provider를 다시 호출하지 않는다. [non-streaming response finalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1163-L1193) [streaming response finalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1195-L1247) [after_run order and skip rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L543-L584)

### Python: per-service-call history consistency

1. `PerServiceCallHistoryPersistingMiddleware`는 service-call 메시지를 input/context로 다시 분해해 per-call `SessionContext`를 만들고, service가 history를 저장하지 않는 경우에만 local `HistoryProvider.before_run()`을 호출한다. [prepare per-call context](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1433-L1490)
2. local persistence 모드에서는 provider-loaded history + new input으로 outgoing request를 재구성하고, local sentinel conversation id를 leaf client로 보내지 않도록 strip한다. [local-history request reconstruction](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1511-L1590)
3. response가 돌아오면 middleware가 provider `after_run()`을 reverse order로 호출해 call-by-call persistence를 수행하고, local mode에서는 follow-up tool loop가 필요할 때 `LOCAL_HISTORY_CONVERSATION_ID` sentinel을 response에 찍는다. service-stored mode에서는 real conversation id를 그대로 유지한다. [per-call persistence and sentinel](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1492-L1568)
4. `require_per_service_call_history_persistence`는 existing service-managed conversation과 local-history simulation을 섞지 못하게 막는다. service가 실제 history를 저장하지 않는 상황에서 live `conversation_id`가 있으면 request 단계에서 즉시 에러다. [conversation-id guard](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L929-L953)

### Python: message injection queue

1. queue는 `session.state["message_injection.pending_messages"]`에 놓이고 global `_MESSAGE_INJECTION_LOCK`으로 보호된다. [pending queue state and lock](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L63-L67)
2. non-streaming path는 “drain queue → service call → actionable follow-up request 없고 queue가 다시 찼으면 empty input으로 재호출” loop를 돈다. streaming path도 같은 규칙을 `ResponseStream` finalizer 위에서 재현한다. [non-streaming injection loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1360-L1380) [streaming injection loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1381-L1430)

### .NET: split pipeline

1. `ChatClientAgent`는 normal run에서 `ChatHistoryProvider`로 history를 먼저 불러오고, 그 결과 위에 `AIContextProvider`들을 순서대로 적용한다. 다만 continuation token path와 per-service-call persistence active path에서는 agent-level history load를 건너뛴다. [agent history/context assembly](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L738-L807)
2. `MessageInjectingChatClient`는 per-session queue를 drain해서 service를 호출하고, actionable function call이 없으면서 queue가 비어 있지 않으면 internal loop를 돌며 `ConversationId`도 다음 iteration options로 넘긴다. [MessageInjectingChatClient non-streaming loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L66-L109) [conversation id propagation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L370-L389)
3. `PerServiceCallChatHistoryPersistingChatClient`는 framework-managed history면 provider load/store와 sentinel `LocalHistoryConversationId`를 소유하고, service-managed history면 provider load를 건너뛰되 real `ConversationId`를 session에 call-by-call 기록한다. streaming early-exit에서는 best-effort로 input-only persistence도 수행한다. [PerServiceCallChatHistoryPersistingChatClient behavior](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L13-L75) [non-streaming implementation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L86-L139) [streaming implementation and cooperative early-exit persistence](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L141-L306)

## 상태·영속화

- Python `SessionContext`는 항상 ephemeral이고, provider durability는 `session.state[source_id]` 또는 provider-owned external backend에만 있다. `InMemoryHistoryProvider`는 `state["messages"]`를 append-only로 유지한다. [InMemoryHistoryProvider state model](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1990-L2064)

[FileHistoryProvider storage and security](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2068-L2095) [read/write path and locks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2172-L2333)

## 동시성·스트리밍·취소

- Python queue injection은 single process에서 `_MESSAGE_INJECTION_LOCK` 하나로 보호되고, `FileHistoryProvider`는 동일 session file에 대해 event-loop-local `asyncio.Lock`과 process-local `threading.Lock`을 겹쳐 써서 overlap append/read를 막는다. - `.NET` per-service-call persistence는 streaming consumer가 mid-stream에서 cooperative early exit해도 input messages를 best-effort로 persist하고 enumerator는 항상 dispose한다. 모든 public paths는 `CancellationToken`을 노출한다. ## 오류·보안

- Python `HistoryProvider`와 `.NET` `ChatHistoryProvider`는 둘 다 loaded history를 framework가 validate/sanitize하지 않으며, storage compromise 시 indirect prompt injection과 role spoofing이 가능하다고 직접 경고한다. - Python `AIContext`/memory 쪽과 `.NET` `AIContextProvider` 계열도 retrieved context를 신뢰하지 말라고 문서화한다. 특히 CosmosMemory provider는 LLM-generated user summary를 instructions가 아니라 “untrusted reference information” user message로 넣는다. [`.NET` AIContextProvider security remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L34-L40) [CosmosMemory anti-prompt-injection framing](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L392-L413)
- Python `FileHistoryProvider`는 path traversal을 encoded fallback filename과 `resolve().is_relative_to()`로 막지만, plaintext local storage / no cross-process locking / no encryption이라는 한계를 그대로 문서화한다. invalid JSONL/MessagePack은 `ValueError`를 던진다. [FileHistoryProvider security posture](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2076-L2085) [read-path errors](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2235-L2309)

## chat history persistence consistency

- Python은 `require_per_service_call_history_persistence=True`이면 history provider를 once-per-run에서 분리해 middleware가 소유하도록 하고, local-history mode에서는 sentinel conversation id를 써서 function loop를 service-managed처럼 보이게 만든다. service-stored mode에서는 provider load를 건너뛰고 real `service_session_id`를 call-by-call 갱신한다. [ChatClientAgentOptions remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L94-L151) [PerServiceCallChatHistoryPersistingChatClient summary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L13-L55)

## 문서 차이

- ADR 0016은 zero-config `InMemoryHistoryProvider` auto-add 조건을 “no providers configured and `options.conversation_id` is set or `options.store` is True”라고 적지만, reviewed production code는 **반대로** session이 있고 load-enabled history provider가 없고 `conversation_id` / `service_session_id` / service-side storage가 모두 없을 때만 auto-add한다. 구현이 최신 authoritative source다. [ADR-0016 design consideration row 4](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0016-python-context-middleware.md#L120-L129) [actual auto-add condition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1348-L1368)
- Python `FoundryMemoryProvider` docstring은 `scope`가 `None`이면 `session_id`를 쓴다고 설명하지만, 실제 constructor는 `scope`가 falsy면 즉시 `ValueError("scope is required")`를 던진다. reviewed snapshot에서는 코드가 문서보다 더 엄격하다. [docstring saying scope can be None](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/foundry/agent_framework_foundry/_memory_provider.py#L57-L65) [constructor enforcing scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/foundry/agent_framework_foundry/_memory_provider.py#L132-L141)
- reviewed decision docs는 `.NET` per-service-call persistence ADR 0022를 명시적으로 갖지만, Python의 `_RunPersistenceGate`, `MessageInjectionMiddleware`, `PerServiceCallHistoryPersistingMiddleware`, `origin_session_ids` attribution은 production source/tests가 더 최신이고 자세하다. 이 영역은 reviewed docs보다 source가 우선이다. [ADR-0022 scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0022-chat-history-persistence-consistency.md#L10-L121) [Python run-persistence/message-injection implementation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1014-L1612)

## Java 결정

- Java core는 `.NET`처럼 history/context/message-injection을 별개 객체로 쪼개기보다, **Python-style `SessionContext` + `ContextProvider` hooks**를 기본 모델로 채택하는 편이 좋다. 이유는 message attribution, `origin_session_ids`, provider-added middleware, `context.response` post-processing을 한 surface에서 표현할 수 있기 때문이다. `.NET` surface는 interop adapter나 compatibility layer로만 참고한다. [Python unified context surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L699) [`.NET` split surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L15-L41)
- Java `HistoryProvider`는 Python처럼 `ContextProvider` subtype으로 두고, `loadMessages/storeInputs/storeContextMessages/storeContextFrom/storeOutputs` flag를 first-class API로 노출한다. 그래야 audit sink / evaluation sink / primary history를 하나의 contract로 재사용할 수 있다. [Python HistoryProvider flags](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L936)
- Java는 per-service-call history persistence와 message injection을 **옵트인**으로 유지한다. 기본은 end-of-run atomicity, opt-in일 때만 sentinel / per-call persistence / queue loop를 켜는 것이 `.NET` ADR와 Python 구현을 동시에 만족한다. [ADR-0022 outcome](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0022-chat-history-persistence-consistency.md#L74-L121) [Python per-call opt-in](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L929-L953) [`.NET` option](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L94-L180)
- Java memory providers는 retrieved memory를 instruction이 아니라 **untrusted context message**로 넣고, storage scope와 retrieval scope를 분리해야 한다. user summary 같은 synthesized memory도 same rule을 따른다. [Mem0 split scopes](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/mem0/agent_framework_mem0/_context_provider.py#L50-L62) [CosmosMemory untrusted summary rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L392-L413)
- Java file-backed history가 필요하다면 session snapshot store와 섞지 말고, Python `FileHistoryProvider`처럼 append-only JSONL/MessagePack history channel로 분리한다. file-name encoding, resolved-path validation, per-file locking을 같이 가져가야 한다. [FileHistoryProvider append-only design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2068-L2333)
- hosted-only memory scope helper는 Java hosting layer가 trusted hosted user context를 주는 module에만 둔다. 그런 hosted context가 없으면 helper는 fail-fast해야 하며, generic core module에 숨겨 넣지 않는다. [HostedFoundryMemoryProviderScopes hosted-only failure mode](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedFoundryMemoryProviderScopes.cs#L21-L43)
