# 09-history-context-memory

This document covers only the **history/context/memory surface** of snapshot `d0a4165f`. It explains mainly the Python side's `SessionContext`/`ContextProvider`/`HistoryProvider`/`InMemoryHistoryProvider`/`FileHistoryProvider`, message injection, per-service-call history persistence, and the provider memory boundary, and compares how the `.NET` side splits the same problem across `ChatHistoryProvider`/`AIContextProvider`/`MessageAIContextProvider`/`MessageInjectingChatClient`/`PerServiceCallChatHistoryPersistingChatClient`. The session snapshot schema and durable session serialization belong to [08-sessions](./08-sessions.md), the compaction policy and the ownership of the `_excluded` marker to [11-compaction](./11-compaction.md), and harness file memory / structured memory to [12-harness](./12-harness.md). [Python session/context/history runtime](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L2339) [.NET history/context abstractions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L15-L350) [.NET message injection / per-call persistence](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L14-L391)

## State/purpose

- Python's central abstraction is the `SessionContext`, newly created on every `agent.run()`; providers add messages / instructions / tools / middleware to it and read `context.response` after the run. `SessionContext` holds `session_id`, `service_session_id`, `input_messages`, ordered `context_messages`, ordered `middleware`, `options`, and `metadata` all together. [SessionContext fields and lifecycle](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L560)
- The purpose of the Python `ContextProvider` is to unify “pre-run injection plus post-run extraction” into a single hooks pattern. The provider-scoped `state` always lives in `AgentSession.state[source_id]`, and the design is that a provider instance does not keep session-specific state in its own fields. [ContextProvider contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L736-L806)
- The Python `HistoryProvider` is a subtype of `ContextProvider` responsible for conversation history load/store. A single type covers primary memory, audit/logging, and evaluation sinks, changing role through the combination of `load_messages`, `store_inputs`, `store_context_messages`, `store_context_from`, and `store_outputs`. [HistoryProvider purpose and flags](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L936)
- `.NET` does not gather the same concerns into one `SessionContext`; it separates persistent history into `ChatHistoryProvider`, transient context into `AIContextProvider`/`MessageAIContextProvider`, loop-level message injection into `MessageInjectingChatClient`, and per-service-call consistency into `PerServiceCallChatHistoryPersistingChatClient`. [ChatHistoryProvider role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L15-L50) [AIContextProvider role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L15-L41) [MessageInjectingChatClient role](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L14-L40)

## Boundary

- This document does not directly explain **session identity / the durable snapshot format / the session store**. History/context providers depend on `AgentSession.state` or the `.NET` `AgentSession.StateBag`, but the snapshot envelope, versioning, quarantine, and hosted session routing belong to [08-sessions](./08-sessions.md). The Python source likewise declares only the boundary that provider custom state needs a `register_state_type()` registration when it enters a persisted session. [HistoryProvider state-registration boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L891-L900) [.NET provider session-state helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ProviderSessionState%7BTState%7D.cs#L9-L25)
- Compaction is not the subject of this document. On the history load side, however, `InMemoryHistoryProvider.skip_excluded` and `FileHistoryProvider.skip_excluded` expose only whether to ignore the `_excluded` marker. The compaction rules, exclusion authoring, and reducer ownership are handed to [11-compaction](./11-compaction.md). [InMemoryHistoryProvider skip_excluded](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2001-L2048) [FileHistoryProvider skip_excluded](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2097-L2199)
- The harness's file memory / advanced structured memory is treated in this document only as “a higher-level feature that consumes the core context provider seam”. The actual file-memory namespace, transcript extraction, and topic memory belong to [12-harness](./12-harness.md). In the core, `SessionContext.extend_messages(...)`, `extend_tools(...)`, and `extend_middleware(...)` are the common seams such higher-level providers attach to. [SessionContext extension seams](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L567-L699)
- The common boundary of provider memory (Mem0 / Cosmos / Foundry and so on) is that it “**does not use session state as an identity source**, reads an external memory store using provider-scoped state and an explicit scope, puts the result into the model as an **untrusted context message**, and after the run extracts memory from the input/response to update the external store”. [Mem0 explicit storage vs retrieval scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/mem0/agent_framework_mem0/_context_provider.py#L44-L62) [CosmosMemory untrusted user-summary injection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L382-L413) [FoundryMemory stores and retrieves via AIContextProvider](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry/Memory/FoundryMemoryProvider.cs#L22-L31)

## APIs and types

### Python

- `SessionContext.extend_messages()` assigns source attribution automatically and deduplicates the optional `origin_session_ids` to leave cross-session memory provenance. `extend_tools()` stamps `context_source` onto the tool metadata, and `extend_middleware()` allows only chat/function middleware. [extend_messages](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L567-L642) [extend_tools](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L654-L669) [extend_middleware](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L671-L699)
- The `HistoryProvider` subclass contract is the two methods `get_messages(session_id, *, state=...)` and `save_messages(session_id, messages, *, state=...)`. The default `before_run`/`after_run` combine them, and the approval control wrapper is cleaned up automatically on load. [HistoryProvider abstract methods](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L938-L1012) [approval-control filter](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L814-L876)
- `InMemoryHistoryProvider` uses only the provider-scoped `state["messages"]` and has no separate instance state. `FileHistoryProvider` additionally exposes `storage_path`, `serialization_format`, the deprecated `dumps`/`loads`, and `skip_excluded`. [InMemoryHistoryProvider API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1990-L2064) [FileHistoryProvider API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2066-L2170)
- The public message injection seams are the free function `enqueue_messages(session, messages)` and `MessageInjectionMiddleware.enqueue_messages()` / `get_pending_messages()`. The queue key is `message_injection.pending_messages`. [pending-message key and enqueue API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L63-L67) [enqueue_messages and middleware API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1279-L1333)

### .NET

- The `.NET` transient context payload is `AIContext { Instructions, Messages, Tools }`, and `Messages` may be persisted by service-managed history or by a `ChatHistoryProvider`. `AIContextProvider` merges and stores this payload through the filtered `InvokingContext` / `InvokedContext`. [AIContext payload](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContext.cs#L8-L109) [AIContextProvider API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L42-L362)
- The `.NET` `MessageAIContextProvider` is a message-only specialization, and the base `AIContextProvider` takes charge of source stamping and merging. [MessageAIContextProvider API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/MessageAIContextProvider.cs#L15-L212)

[ChatHistoryProvider merge/store API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L111-L299)

[MessageInjectingChatClient public methods](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L180-L243) [RequirePerServiceCallChatHistoryPersistence / EnableMessageInjection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L94-L180)

## Execution flow

### Python: provider pipeline

1. The preparation stage of `RawAgent.run()` interprets whether service storage applies and resolves the `conversation_id`, and then adds an `InMemoryHistoryProvider` automatically only when **there is a session, there is no load-enabled history provider**, and there is no trace of a service-managed conversation either. [auto-inject in-memory history](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1348-L1368)
2. The `SessionContext` is created from the provider session's ids and the input messages. `before_run` is called in forward order; when per-service-call history persistence is active the `HistoryProvider` is skipped on the once-per-run path, and a provider with `load_messages=False` is skipped as well. [SessionContext construction and before_run order](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1567-L1600)
3. At the end of the run the framework plugs the full `AgentResponse` into `session_context._response` and then calls `after_run` in reverse order. When per-service-call persistence already owns the history provider, the once-per-run `after_run` does not call that provider again. [non-streaming response finalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1163-L1193) [streaming response finalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1195-L1247) [after_run order and skip rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L543-L584)

### Python: per-service-call history consistency

1. `PerServiceCallHistoryPersistingMiddleware` decomposes the service-call messages back into input/context to build a per-call `SessionContext`, and calls the local `HistoryProvider.before_run()` only when the service does not store history. [prepare per-call context](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1433-L1490)
2. In local persistence mode it rebuilds the outgoing request from the provider-loaded history plus the new input, and strips the local sentinel conversation id so it is not sent to the leaf client. [local-history request reconstruction](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1511-L1590)
3. When the response comes back, the middleware calls the provider `after_run()` in reverse order to perform call-by-call persistence, and in local mode stamps the `LOCAL_HISTORY_CONVERSATION_ID` sentinel onto the response when a follow-up tool loop is needed. In service-stored mode it keeps the real conversation id as is. [per-call persistence and sentinel](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1492-L1568)
4. `require_per_service_call_history_persistence` prevents mixing an existing service-managed conversation with a local-history simulation. When there is a live `conversation_id` in a situation where the service does not actually store history, it is an immediate error at the request stage. [conversation-id guard](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L929-L953)

### Python: message injection queue

1. The queue lives in `session.state["message_injection.pending_messages"]` and is protected by the global `_MESSAGE_INJECTION_LOCK`. [pending queue state and lock](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L63-L67)
2. The non-streaming path runs a “drain the queue → service call → if there is no actionable follow-up request and the queue has filled up again, call again with empty input” loop. The streaming path reproduces the same rule on top of the `ResponseStream` finalizer. [non-streaming injection loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1360-L1380) [streaming injection loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1381-L1430)

### .NET: split pipeline

1. In a normal run `ChatClientAgent` loads the history through the `ChatHistoryProvider` first and then applies the `AIContextProvider` instances in order on top of that result. On the continuation token path and on the per-service-call persistence active path, however, it skips the agent-level history load. [agent history/context assembly](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L738-L807)
2. `MessageInjectingChatClient` drains the per-session queue and calls the service, and when there is no actionable function call while the queue is not empty it runs an internal loop and also passes the `ConversationId` into the next iteration options. [MessageInjectingChatClient non-streaming loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L66-L109) [conversation id propagation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L370-L389)
3. `PerServiceCallChatHistoryPersistingChatClient` owns the provider load/store and the sentinel `LocalHistoryConversationId` when the history is framework-managed, and when the history is service-managed it skips the provider load but records the real `ConversationId` into the session call by call. On a streaming early exit it also performs best-effort input-only persistence. [PerServiceCallChatHistoryPersistingChatClient behavior](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L13-L75) [non-streaming implementation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L86-L139) [streaming implementation and cooperative early-exit persistence](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L141-L306)

## State and persistence

- The Python `SessionContext` is always ephemeral, and provider durability lives only in `session.state[source_id]` or in a provider-owned external backend. `InMemoryHistoryProvider` keeps `state["messages"]` append-only. [InMemoryHistoryProvider state model](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1990-L2064)
- The Python `FileHistoryProvider` uses one append-only file per session. The default is JSON Lines and the opt-in is length-prefixed MessagePack; it uses an encoded filename stem and resolved-path validation to prevent storage root escape, and serializes append/read on the same file with a process-local thread lock plus an event-loop-local async lock. [FileHistoryProvider storage and security](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2068-L2095) [read/write path and locks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2172-L2333)
- Python durable side effects can be deferred behind the `_RunPersistenceGate` when egress-enforcement middleware has installed a gate. That gate collects pending persistence callables per run identity and either `flush()`es or `drop()`s them after the verdict. [run-persistence gate design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1014-L1243)
- For `.NET` provider state, `ProviderSessionState<TState>` reads and writes JSON-serialized typed state in the `AgentSession.StateBag`. `InMemoryChatHistoryProvider` puts a `State.Messages` list on top of this helper, and the queueing chat clients also use their own key in the `StateBag`. [ProviderSessionState](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ProviderSessionState%7BTState%7D.cs#L16-L87) [InMemoryChatHistoryProvider state storage](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/InMemoryChatHistoryProvider.cs#L29-L133) [MessageInjectingChatClient queue state key](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L42-L56)
- Session snapshot serialization itself is the scope of 08. The only fact confirmable in this document is the boundary that “history/context/memory providers may put session-local state into the snapshot”. [Python provider state registration boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L742-L751) [`.NET` session state bag exposure](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L34-L37)

## Extension points

- A Python custom history provider only has to implement `HistoryProvider.get_messages()` / `save_messages()`, and the load/store policy is provided by the base flags. A custom context provider overrides `before_run()` / `after_run()` and uses the `SessionContext` mutation API. [HistoryProvider subclass contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L887-L1012) [ContextProvider override surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L766-L806)
- When a Python provider stores a custom runtime type in session state it must call `register_state_type()` at module import time. Plain JSON-native values need no registration. [register_state_type guidance](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L742-L751) [register_state_type API](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L268-L335)
- The `.NET` extension points are `ChatHistoryProvider.ProvideChatHistoryAsync()` / `StoreChatHistoryAsync()` and `AIContextProvider.ProvideAIContextAsync()` / `StoreAIContextAsync()`. ## Concurrency, streaming, and cancellation

- Python queue injection is protected by the single `_MESSAGE_INJECTION_LOCK` inside one process, and `FileHistoryProvider` overlaps an event-loop-local `asyncio.Lock` with a process-local `threading.Lock` on the same session file to prevent overlapping append/read. [message injection lock](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L65-L66) [file lock stripes](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2087-L2095) [async lock lookup](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2316-L2333)
- When a Python toolized sub-agent shares the parent session, the state dict is shared but the `service_session_id` is forcibly cleared on the child session. The reason is to keep concurrent `asyncio.gather` tool invocations from overwriting the same continuation handle. [shared state but isolated service_session_id](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L659-L669)
- The Python Mem0 provider does not swallow `asyncio.CancelledError` alone during a parallel partition search and re-raises it. Other task failures are logged and a partial merge is allowed. [Mem0 cancellation and partial-failure handling](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/mem0/agent_framework_mem0/_context_provider.py#L181-L229)
- `.NET` message injection keeps a per-session queue lock in a `ConditionalWeakTable<AgentSession, SemaphoreSlim>`. The non-streaming path aggregates usage across the whole loop, and the streaming path tracks update-level actionable function calls and the latest conversation id. [session-scoped semaphore locking](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L49-L56) [usage aggregation and loop exit](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L76-L109) [streaming loop](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L112-L177)
- `.NET` per-service-call persistence persists the input messages on a best-effort basis even when a streaming consumer cooperatively exits early mid-stream, and always disposes the enumerator. Every public path exposes a `CancellationToken`. [cooperative early-exit persistence](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L232-L260) [CancellationToken-bearing provider/client APIs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L111-L299)

## Errors and security

- The Python `HistoryProvider` and the `.NET` `ChatHistoryProvider` both warn directly that the framework does not validate/sanitize loaded history and that indirect prompt injection and role spoofing are possible when the storage is compromised. [Python history-provider warning via design contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L880-L900) [`.NET` ChatHistoryProvider security remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/ChatHistoryProvider.cs#L39-L49)
- The Python `AIContext`/memory side and the `.NET` `AIContextProvider` family also document that retrieved context must not be trusted. The CosmosMemory provider in particular puts an LLM-generated user summary in as an “untrusted reference information” user message rather than as instructions. [`.NET` AIContextProvider security remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L34-L40) [CosmosMemory anti-prompt-injection framing](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L392-L413)
- The Python `FileHistoryProvider` blocks path traversal with an encoded fallback filename and `resolve().is_relative_to()`, but documents the limits of plaintext local storage / no cross-process locking / no encryption as they are. Invalid JSONL/MessagePack raises a `ValueError`. [FileHistoryProvider security posture](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2076-L2085) [read-path errors](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2235-L2309)

[Python reject real conversation id in local mode](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1531-L1539) [`.NET` conflict detection](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L819-L849)
- The `.NET` hosted Foundry memory helper does not work unless the hosting layer supplies a `HostedSessionContext`. Using it as is in a console/local app is an `InvalidOperationException`. [HostedFoundryMemoryProviderScopes hosted-only boundary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedFoundryMemoryProviderScopes.cs#L21-L43)

## chat history persistence consistency

- When `require_per_service_call_history_persistence=True`, Python detaches the history provider from the once-per-run path so that the middleware owns it, and in local-history mode uses a sentinel conversation id to make the function loop look service-managed. In service-stored mode it skips the provider load and updates the real `service_session_id` call by call. [Python per-call middleware design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1433-L1612) [run preparation skip rules](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1379-L1527)
- `.NET` solves the same consistency problem with the `ChatClientAgentOptions.RequirePerServiceCallChatHistoryPersistence` option and the `PerServiceCallChatHistoryPersistingChatClient` decorator. With the option off it guarantees only end-of-run persistence, and with it on it guarantees per-service-call persistence and intermediate `ConversationId` capture. [ChatClientAgentOptions remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L94-L151) [PerServiceCallChatHistoryPersistingChatClient summary](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/PerServiceCallChatHistoryPersistingChatClient.cs#L13-L55)
- The upstream decision record defines this problem as a `.NET` `ChatClientAgent` plus tool loop discrepancy and chose opt-in per-service-call persistence. The reviewed Python production code already implements similar middleware, but no document explaining the Python version as a separate ADR was found in the reviewed decision docs. [ADR-0022 problem and outcome](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0022-chat-history-persistence-consistency.md#L10-L121) [Python per-call implementation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1433-L1612)

## Documentation differences

- ADR 0016 states the zero-config `InMemoryHistoryProvider` auto-add condition as “no providers configured and `options.conversation_id` is set or `options.store` is True”, but the reviewed production code **does the opposite** and auto-adds only when there is a session, there is no load-enabled history provider, and `conversation_id` / `service_session_id` / service-side storage are all absent. The implementation is the newer authoritative source. [ADR-0016 design consideration row 4](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0016-python-context-middleware.md#L120-L129) [actual auto-add condition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1348-L1368)
- The Python `FoundryMemoryProvider` docstring explains that `session_id` is used when `scope` is `None`, but the actual constructor immediately throws `ValueError("scope is required")` when `scope` is falsy. In the reviewed snapshot the code is stricter than the documentation. [docstring saying scope can be None](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/foundry/agent_framework_foundry/_memory_provider.py#L57-L65) [constructor enforcing scope](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/foundry/agent_framework_foundry/_memory_provider.py#L132-L141)
- The reviewed decision docs explicitly carry the `.NET` per-service-call persistence ADR 0022, but for Python's `_RunPersistenceGate`, `MessageInjectionMiddleware`, `PerServiceCallHistoryPersistingMiddleware`, and `origin_session_ids` attribution the production source/tests are newer and more detailed. In this area the source takes precedence over the reviewed docs. ## Java decisions

- Rather than splitting history/context/message-injection into separate objects as `.NET` does, the Java core is better off adopting the **Python-style `SessionContext` plus `ContextProvider` hooks** as its base model. The reason is that message attribution, `origin_session_ids`, provider-added middleware, and `context.response` post-processing can all be expressed on one surface. The `.NET` surface is referenced only as an interop adapter or compatibility layer. [Python unified context surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L500-L699) [`.NET` split surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs#L15-L41)
- The Java `HistoryProvider` should be a `ContextProvider` subtype as in Python, and should expose the `loadMessages/storeInputs/storeContextMessages/storeContextFrom/storeOutputs` flags as first-class API. Only then can an audit sink / evaluation sink / primary history be reused through a single contract. [Python HistoryProvider flags](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L879-L936)
- Java keeps per-service-call history persistence and message injection **opt-in**. Making end-of-run atomicity the default and turning on the sentinel / per-call persistence / queue loop only on opt-in satisfies the `.NET` ADR and the Python implementation at the same time. [ADR-0022 outcome](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/docs/decisions/0022-chat-history-persistence-consistency.md#L74-L121) [Python per-call opt-in](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L929-L953) [`.NET` option](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L94-L180)
- Java memory providers must put retrieved memory in as an **untrusted context message** rather than as instructions, and must separate the storage scope from the retrieval scope. Synthesized memory such as a user summary follows the same rule. [Mem0 split scopes](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/mem0/agent_framework_mem0/_context_provider.py#L50-L62) [CosmosMemory untrusted summary rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/azure-cosmos-memory/agent_framework_azure_cosmos_memory/_context_provider.py#L392-L413)
- If file-backed history is needed in Java, it must not be mixed with the session snapshot store and should be separated into an append-only JSONL/MessagePack history channel as in the Python `FileHistoryProvider`. File-name encoding, resolved-path validation, and per-file locking have to be taken along with it. [FileHistoryProvider append-only design](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L2068-L2333)
- A hosted-only memory scope helper belongs only in a module where the Java hosting layer supplies a trusted hosted user context. Without such a hosted context the helper must fail fast, and it must not be hidden inside a generic core module. [HostedFoundryMemoryProviderScopes hosted-only failure mode](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/HostedFoundryMemoryProviderScopes.cs#L21-L43)
