## 상태/스냅샷

- 이 문서는 고정 커밋 `d0a4165f170193ba1d026a259af40d35bb7eaefe` 기준의 declarative 계층만 다룬다. 범위는 네 갈래다.

  3. **Agent / tool / HTTP / external-input action executors**
  4. **MCP declarative integration**
  5. **.NET generator / source generator와 Python 구현 차이**

## 목적·경계

### 목적

- declarative 계층의 목적은 **코드가 아니라 YAML/asset schema로 agent와 workflow를 정의하고**, 이를 **실행 가능한 runtime graph와 provider/tool/http/mcp integration**으로 변환하는 것이다.  
  - .NET은 workflow 쪽 declarative lowering과 declarative action execution에 초점을 둔다.
  - Python은 여기에 더해 YAML prompt-agent asset creation까지 포함한다.  
  ([.NET declarative workflow builder purpose](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowBuilder.cs#L14-L18), [Python WorkflowFactory purpose](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L43-L50), [Python AgentFactory purpose](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_loader.py#L143-L149))

### 경계

- 포함 범위:
  - agent asset YAML 형태와 schema normalization
  - declarative workflow definition shape
  - workflow graph lowering과 root executor behavior
  - declarative state / PowerFx env / path safety
  - action executors (`InvokeAzureAgent`, `InvokeFunctionTool`, `InvokeMcpTool`, `HttpRequestAction`, `Question`, `RequestExternalInput`, `SendActivity`, control-flow lowering)
  - MCP integration package/handler
  - .NET source generation/JSON source generation과 Python runtime-driven 구현 차이
- 제외 범위:
  - generic core workflow graph/runtime 자체
  - orchestration builders
  - generic workflow-as-agent composition
  - host/web transport  
  inspected 코드 기준으로 이 문서는 .NET `DeclarativeWorkflowBuilder`, `WorkflowActionVisitor`, `DeclarativeWorkflowExecutor`, `ObjectModel/*`, `DeclarativeWorkflowJsonOptions`, `DefaultHttpRequestHandler`, `DefaultMcpToolHandler`와 Python `_loader.py`, `_models.py`, `_workflows/*`, declarative tests, declarative asset samples를 직접 대상으로 한다. ([.NET workflow lowering surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs#L15-L64), [Python workflow builder surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_builder.py#L111-L129), [Python agent schema/model surface](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_models.py#L83-L140))

## 상세 실행 흐름

### 하위 기능 1. Declarative agent assets / schema

- Python declarative agent asset의 canonical YAML shape는 sample 파일들이 보여 준다. `OpenAI.yaml`은 `kind: Prompt`, `model.provider`, `model.apiType`, `connection`, `outputSchema.properties`를 사용하고, `GetWeather.yaml`은 `tools` 아래 function tool과 parameter schema/bindings를 선언한다. ([OpenAI agent sample](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/declarative-agents/agent-samples/openai/OpenAI.yaml#L1-L29), [chatclient function-tool sample](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/declarative-agents/agent-samples/chatclient/GetWeather.yaml#L1-L30))
- Python `AgentFactory.create_agent_from_dict(...)`는 YAML dict를 `agent_schema_dispatch(...)`로 schema object로 바꾼 뒤, 반드시 `PromptAgent`여야 한다고 강제한다. 그 다음 chat client를 만들고, `tools`와 `outputSchema`를 `default_options`로 합쳐 `Agent`를 생성한다. ([AgentFactory create_agent_from_dict](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_loader.py#L418-L484))
- Python asset loader는 PowerFx expression을 YAML scalar에 적용할 수 있다. `_try_powerfx_eval(...)`는 `=`로 시작하는 값을 평가하고, `safe_mode=True`면 `Env` 심볼을 막고, `safe_mode=False`일 때만 `Env`에 `os.environ`을 넣는다. README가 experimental declarative agent path임을 밝히는 것과 맞물려, Python asset loader는 신뢰 경계가 중요한 surface다. ([safe_mode context and PowerFx eval](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_models.py#L37-L80), [AgentFactory safe_mode docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_loader.py#L236-L245))
- Python `WorkflowFactory`는 workflow YAML 안의 `agents:` 섹션에서 inline dict, `file:` reference, 또는 pre-registered agent registry를 조합해 agent를 해석할 수 있다. 반면 `connection` 기반 agent definitions는 현재 pre-created agent를 `agents=` parameter로 넘겨야 하며 inline auto-construction은 지원하지 않는다. ([create_workflow_from_definition agents section](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L374-L404), [_create_agent_from_def](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L549-L585))
- .NET inspected 범위에서는 workflow YAML sample만 공식적으로 문서화되어 있다. workflow sample README는 declarative workflow가 단일 YAML 파일이며 `DeclarativeWorkflowBuilder.Build(...)`로 로컬 실행 가능하다고만 설명한다. inspected scope에서 Python `AgentFactory`와 같은 YAML prompt-agent asset loader는 확인되지 않았다. ([workflow-samples README](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/declarative-agents/workflow-samples/README.md#L1-L17))

### 하위 기능 2. Declarative workflow graph / runtime / state

- .NET declarative workflow는 `Build<TInput>(TextReader yamlReader, DeclarativeWorkflowOptions options, ...)`가 시작점이다. YAML root는 `YamlSerializer.Deserialize<BotElement>`로 읽고, root는 `AdaptiveDialog`여야 하며 `"Workflow"`는 `"AdaptiveDialog"` alias다. ([.NET Build<TInput>](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowBuilder.cs#L51-L88), [ReadWorkflow root check](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowBuilder.cs#L90-L101))
- .NET lowering은 `WorkflowActionVisitor`가 수행한다. 이 visitor는 action scope, condition group, goto, foreach, question, request external input 등을 graph node와 edge로 분해하고, 마지막엔 `WorkflowModelBuilder`를 통해 core `WorkflowBuilder`를 만든다. telemetry가 켜져 있으면 build 시 OpenTelemetry 설정도 붙는다. ([WorkflowActionVisitor complete](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs#L35-L64), [scope/condition/loop lowering](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs#L66-L208), [question/request-external-input lowering](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs#L248-L296))
- .NET root executor `DeclarativeWorkflowExecutor<TInput>`는 `TInput` 외에도 `string`, `ChatMessage`, `IEnumerable<ChatMessage>`, `ChatMessage[]`, `TurnToken`을 받아 chat protocol hosting과 direct invocation을 동시에 만족시킨다. 실제 inbound `TurnToken`은 no-op이고, non-token input만 graph advance를 트리거한다. ([DeclarativeWorkflowExecutor input shapes](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/DeclarativeWorkflowExecutor.cs#L17-L33), [chat protocol route registration](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/DeclarativeWorkflowExecutor.cs#L57-L145))
- Python declarative workflow는 `WorkflowFactory.create_workflow_from_definition(...)`가 workflow name/description을 결정하고, `agents:`를 생성·병합하고, `DeclarativeEnvConfig`를 만든 뒤, `DeclarativeWorkflowBuilder`로 graph를 만든다. 이 builder는 top-level `actions:` 또는 `trigger.actions` 둘 다 받아들인다. ([WorkflowFactory create_workflow_from_definition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L321-L404), [workflow normalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L479-L547))
- Python `DeclarativeWorkflowBuilder`는 `_workflow_entry` join node를 start executor로 두고, action executors, evaluators, loop helper nodes, goto back-edges를 만들어 core workflow graph로 낮춘다. empty workflow는 거부되고, schema validation과 circular goto detection도 build 전에 수행한다. ([DeclarativeWorkflowBuilder init/build](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_builder.py#L132-L239), [validation pre-pass](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_builder.py#L241-L334))

## 동시성·스트리밍·취소

- declarative workflow는 generic core runtime 위에 올라가므로 superstep concurrency/cancel 정책 자체를 바꾸지는 않는다. declarative-specific 차이는 **action executor 내부에서 workflow를 어디서 멈추고 다시 이어 가는지**다.
- .NET `DeclarativeWorkflowExecutor<TInput>`는 `ChatMessage[]`/`IEnumerable<ChatMessage>`를 받을 때 여러 message를 순회하되 마지막 message에서만 `finalizeTurn=true`로 `SendResultMessageAsync(...)`를 호출한다. `TurnToken`은 no-op이라 host가 보낸 token이 root advance를 이중 트리거하지 않는다. ([multiple chat messages handling](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/DeclarativeWorkflowExecutor.cs#L113-L145), [AdvanceAsync finalizeTurn](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/DeclarativeWorkflowExecutor.cs#L147-L186))
- Python `InvokeAzureAgentExecutor`의 external loop는 user input/agent response를 번갈아 보며 loop condition을 체크한다. 조건이 true면 request_info로 멈추고, false면 `ActionComplete`를 보내 graph를 다시 진행시킨다. ([first loop yield](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_agents.py#L834-L871), [resume and re-evaluate loop condition](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_agents.py#L921-L1010))
- Python HTTP/MCP default handlers are concurrency-safe by contract.  
  - `HttpRequestHandler` protocol doc says implementations must be safe to call concurrently from multiple workflow runs.
  - `DefaultMCPToolHandler` uses async lock + inflight futures for cache/connect coordination.  
  ([HttpRequestHandler concurrency contract](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_http_handler.py#L90-L112), [DefaultMCPToolHandler cache/inflight coordination](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_mcp_handler.py#L220-L229))
- 취소 측면에서 Python HTTP action은 `asyncio.CancelledError`를 잡지 않고 흘려보낸다. .NET HTTP action도 timeout과 caller cancellation을 구분한다. ([Python cancellation not caught](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_http.py#L154-L156), [.NET timeout/cancellation distinction](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/ObjectModel/HttpRequestExecutor.cs#L55-L66))

  - `safe_mode=False`는 trusted YAML일 때만 권장

  ([safe_mode docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_loader.py#L236-L245), [normalize object schemas additionalProperties false](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_models.py#L239-L249))

([origin pinning and redirect/cookie restrictions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative.Mcp/DefaultMcpToolHandler.cs#L206-L247))
- .NET `InvokeMcpToolExecutor`는 approval request에 transport headers를 포함하지 않는다. Python도 header values 대신 names만 surface한다. 즉 양쪽 모두 approval surface에서 secret header leakage를 피하려 한다. ([.NET no headers in approval request](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/ObjectModel/InvokeMcpToolExecutor.cs#L97-L105), [Python header names only](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_executors_mcp.py#L13-L17))
- Python path safety tests pin unsafe object-attribute traversal rejection, making declarative state path resolution a security boundary rather than 편의 기능이다. ([state path safety tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_state_path_safety.py#L90-L133))

- **agent assets loader 존재 여부**: Python은 experimental `AgentFactory`와 rich asset schema model을 갖지만, inspected .NET 범위는 generic YAML prompt-agent loader 대신 workflow YAML loader와 `ResponseAgentProvider` abstraction이 중심이다. - **workflow definition shape**: Python `WorkflowFactory`는 top-level `actions`와 `trigger.actions` 둘 다 허용하지만, .NET builder는 `AdaptiveDialog` root를 읽는 object-model route가 중심이다. ([Python _get_actions_from_def](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_factory.py#L521-L547), [.NET ReadWorkflow root alias](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowBuilder.cs#L90-L101))
- **state safety**: Python declarative는 safe path segments와 `Env` allowlisting을 first-class security feature로 구현하고 tests로 고정한다. inspected .NET 범위에서는 동일 수준의 path safety layer가 별도 public contract로 드러나지 않는다. ([Python path/env safety](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_base.py#L70-L123), [Python path safety tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_state_path_safety.py#L90-L133))

([.NET Roslyn generator](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Generators/ExecutorRouteGenerator.cs#L16-L75), [.NET DeclarativeWorkflowJsonOptions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowJsonOptions.cs#L41-L77), [Python runtime model normalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_models.py#L116-L138))

([.NET secure MCP client creation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative.Mcp/DefaultMcpToolHandler.cs#L206-L247), [Python MCP security note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_mcp_handler.py#L16-L24))

## Java 결정

- Java declarative는 **workflow declarative**와 **agent asset declarative**를 분리된 모듈/패키지로 두는 것이 좋다. Python처럼 두 표면의 성숙도가 다를 수 있으므로, `workflow-declarative`는 stable core addon으로, `agent-assets-declarative`는 preview/experimental로 시작하는 편이 안전하다. ([Python README split](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/README.md#L11-L18))
- Java workflow DSL은 **schema AST → normalized model → graph lowering**의 3단을 명확히 나눠야 한다.
  - Python `_models.py`의 `type→kind` / nested schema normalization
  - Python `_declarative_builder.py`의 graph lowering
  - .NET `WorkflowActionVisitor`의 node decomposition  
  이 세 층을 섞으면 validation, IDE tooling, AOT support가 어려워진다. ([Python schema normalization](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_models.py#L206-L302), [Python graph lowering](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_builder.py#L186-L239), [.NET graph lowering](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/Interpreter/WorkflowActionVisitor.cs#L66-L296))
- Java declarative state는 Python처럼 **safe path resolution**과 **Env allowlisting**을 기본 보안 기능으로 포함해야 한다. generic `Map<String,Object>`만으로 두면 표현식/경로 경계에서 취약점이 생긴다. ([Python Env allowlist](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_base.py#L70-L123), [Python path safety enforcement](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_declarative_base.py#L337-L497))
- Java action handler SPI는 `.NET`처럼 typed interfaces(`HttpRequestHandler`, `McpToolHandler`, `AgentProvider`)를 public contract로 두고, production default와 security-hardened custom implementations를 명시적으로 분리해야 한다. Python default MCP/HTTP handlers가 “no SSRF protection”을 문서화하는 방식도 참고할 만하다. ([.NET IHttpRequestHandler](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/IHttpRequestHandler.cs#L11-L29), [.NET IMcpToolHandler](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/IMcpToolHandler.cs#L10-L41), [Python HTTP security note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_http_handler.py#L1-L18), [Python MCP security note](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/agent_framework_declarative/_workflows/_mcp_handler.py#L16-L24))
- Java AOT/native-image 목표가 있다면 `.NET`처럼 **declarative checkpoint payload의 source-generated serialization metadata**를 별도 모듈로 두는 것이 좋다. Python-style dynamic object encoding은 native-image 환경에서 불리하다. ([DeclarativeWorkflowJsonOptions](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/DeclarativeWorkflowJsonOptions.cs#L15-L77))
- Java tool approval/MCP approval은 Python declarative tests처럼 **`original_request` payload를 source-of-truth**로 삼아야 한다. resumed invocation이 mutable workflow state를 다시 읽어 승인 대기 중에 바뀐 값을 사용하면 안 된다. ([Python approval binding tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/declarative/tests/test_declarative_approval_binding.py#L170-L220), [.NET InvokeRegisteredFunctionAsync uses snapshot](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/ObjectModel/InvokeFunctionToolExecutor.cs#L398-L440))
