# 01-agent-lifecycle

This document covers only the **agent abstraction/lifecycle**, **identity/metadata**, **session creation**, **run entrypoints**, and the **delegation/wrapping boundary** of the Microsoft Agent Framework. Within that scope .NET composes the lifecycle around the `AIAgent`/`DelegatingAIAgent`/`ChatClientAgent`/`AIAgentBuilder` axis, and Python around the `BaseAgent`/`RawAgent`/`Agent`/`SupportsAgentRun` axis. Both implementations agree that “the agent is the top-level abstraction of conversation execution”, but .NET is closer to **async-only methods plus a decorator chain**, while Python is closer to **a layered class composition whose synchronous-looking public `run()` returns an awaitable or a `ResponseStream`**. [AIAgent.cs#L17-L38](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L17-L38) [DelegatingAIAgent.cs#L13-L28](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L13-L28) [_agents.py#L364-L420](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L364-L420) [_agents.py#L1751-L1764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1751-L1764)

## Purpose

The purpose of this feature is to unify subordinate features such as model invocation, session state, tool execution, and provider injection into **a single agent lifecycle surface**. .NET's `AIAgent` defines session creation/serialization/deserialization and the execution API as abstract methods, while Python's `BaseAgent`/`RawAgent` put session creation, the chat-client connection, and the combination of context providers and middleware at the centre of the lifecycle. [AIAgent.cs#L138-L235](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L138-L235) [_agents.py#L463-L507](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L463-L507) [_agents.py#L788-L908](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L788-L908)

## State and snapshot

- In the .NET lifecycle the session snapshot format is **owned by the agent**. `AIAgent` provides `SerializeSessionAsync()` and `DeserializeSessionAsync()` as public APIs, and the implementation controls whether a session type is supported. [AIAgent.cs#L168-L235](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L168-L235)
- For the same reason the .NET `AgentSession` documentation states that “sessions are created by an agent, and because each agent may attach different behavior, reuse across different agents may be impossible”. [AgentSession.cs#L24-L43](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSession.cs#L24-L43)
- In the Python lifecycle the snapshot format is **owned by `AgentSession` and the store, not by the agent**. `AgentSession.to_dict()/from_dict()` is the default snapshot path, and `SessionStore`/`FileSessionStore` are a separate layer that stores that snapshot. [_sessions.py#L1655-L1689](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1655-L1689) [_sessions.py#L1693-L1779](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1693-L1779)

## Run Entry Points

### .NET

- `AIAgent` provides only `RunAsync()` and `RunStreamingAsync()`, each with no-message / string / single chat message / message collection overloads. There is no synchronous blocking run. [AIAgent.cs#L237-L506](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L237-L506)
- `RunAsync(string)` wraps the input string in a `ChatRole.User` message, and `RunStreamingAsync(string)` follows the same rule. [AIAgent.cs#L257-L305](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L257-L305) [AIAgent.cs#L388-L436](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L388-L436)

### Python

- By overload, the public `Agent.run()` returns `Awaitable[AgentResponse]` when `stream=False` and `ResponseStream[AgentResponseUpdate, AgentResponse]` when `stream=True`. That is, the public method looks synchronous but the actual work result is an asynchronous object. [_agents.py#L1766-L1828](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1766-L1828)
- The actual core implementation `RawAgent.run()` has the same shape and accepts `messages`, `session`, `tools`, `options`, `compaction_strategy`, `tokenizer`, `function_invocation_kwargs`, and `client_kwargs`. [_agents.py#L983-L1040](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L983-L1040)
- The message input shape is `AgentRunInputs = str | Content | Message | Sequence[...]`, and `normalize_messages()` normalizes a string or a single content into a user message. [_types.py#L1844-L1881](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L1844-L1881)

## Detailed execution flow

### .NET: the `AIAgent` common wrapper

1. The public `RunAsync(messages, session, options, ct)` sets `CurrentRunContext = new AgentRunContext(...)`. [AIAgent.cs#L334-L342](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L334-L342)  
2. It then calls `RunCoreAsync(...)`. The implementation performs the actual provider/client call there. [AIAgent.cs#L344-L370](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L344-L370)  
3. The public `RunStreamingAsync(...)` likewise builds the context and iterates `RunCoreStreamingAsync(...)`. [AIAgent.cs#L464-L479](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L464-L479)  
4. In streaming, caller code runs after each `yield return`, so the base wrapper restores `CurrentRunContext` again. [AIAgent.cs#L472-L479](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L472-L479)

### .NET: the `ChatClientAgent` concrete flow

1. The constructor clones the mutable `ChatClientAgentOptions` and, unless opted out, decorates the chat client stack with `WithDefaultAgentMiddleware()`. The default chat history provider is `InMemoryChatHistoryProvider` when none is specified. [ChatClientAgent.cs#L122-L137](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L122-L137)
2. The non-streaming `RunCoreAsync()` builds the safe session, the merged chat options, and the input messages with `PrepareSessionAndMessagesAsync()`. [ChatClientAgent.cs#L205-L218](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L205-L218)
3. Because the safe session is late-bound, `EnsureRunContextHasSession()` replaces the ambient run context's session with the actual session. [ChatClientAgent.cs#L219-L222](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L219-L222) [ChatClientAgent.cs#L938-L956](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L938-L956)
4. When the chat client call fails it sends a provider failure notification and rethrows the exception. On success it performs the conversation id update, the author name correction, and the provider success notification, and then returns an `AgentResponse`. [ChatClientAgent.cs#L229-L263](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L229-L263)
5. The streaming path grabs the inner enumerator directly and always disposes it, and on every update performs continuation token wrapping and author name correction. After completion it reassembles the collected updates into a `ChatResponse` and performs the conversation id update and the provider notification. [ChatClientAgent.cs#L321-L401](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L321-L401)

### Python: the `Agent` → `RawAgent` layered flow

1. The public `Agent.run()` passes through the telemetry/middleware layers and then descends via `super().run(...)`. [ _agents.py#L1814-L1845](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1814-L1845)
2. The actual implementation `RawAgent.run()` first prepares the `_prepare_run_context()` coroutine, creates the run identity, and adopts the persistence gate claim. [_agents.py#L1077-L1097](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1077-L1097)
3. When non-streaming it calls `_call_chat_client(ctx, stream=False)` and then builds the final `AgentResponse` with `_parse_non_streaming_response()`. When streaming it calls `_call_chat_client(..., stream=True)` and then `_parse_streaming_response()` attaches transform/result hooks to the `ResponseStream`. ## Delegation / wrapping boundary and extension points

### .NET

- `DelegatingAIAgent` is a **transparent decorator base** that delegates `Id`, `Name`, `Description`, `GetService()`, session create/serialize/deserialize, run, and streaming run entirely to the inner agent. [DelegatingAIAgent.cs#L44-L102](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L44-L102)
- `AIAgentBuilder` stacks agent factories and applies them in reverse order at `Build()` time. Therefore **the factory added first becomes the outermost wrapper**. [AIAgentBuilder.cs#L49-L70](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L49-L70)
- The builder supports the simple `Use(Func<AIAgent,AIAgent>)`, the service-aware `Use(Func<AIAgent,IServiceProvider,AIAgent>)`, anonymous delegating run/runStreaming implementations, and the message context providers wrapper. [AIAgentBuilder.cs#L72-L178](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L72-L178)

### Python

- Python's wrapping is closer to a **layered class composition** than to a chain of agent object decorators. `Agent` multiply inherits `AgentMiddlewareLayer`, `AgentTelemetryLayer`, and `RawAgent`, and the `run()` implementation descends via `super().run(...)`. [_agents.py#L1751-L1764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1751-L1764) [_agents.py#L1814-L1845](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1814-L1845)
- On the chat client side, `BaseChatClient.as_agent()` is a convenience wrapper that produces an `Agent` with the client already attached. [_clients.py#L571-L658](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_clients.py#L571-L658)

### Difference summary

- .NET's wrapping boundary is a **runtime chain of decorator objects**, while Python's wrapping boundary is an **MRO-based layer composition plus an optional middleware pipeline**. [DelegatingAIAgent.cs#L13-L28](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L13-L28) [_agents.py#L1751-L1764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1751-L1764)

- The .NET lifecycle exposes a `CancellationToken` on every core API. ## Java decisions

- For the Java design it is appropriate to compromise between .NET's **explicit agent abstraction plus decorator/builder** and Python's **single public `Agent` entrypoint**. The rationale is that .NET makes the lifecycle boundary and session snapshot ownership explicit while Python simplifies public usability. [AIAgent.cs#L138-L235](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L138-L235) [AIAgentBuilder.cs#L40-L178](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L40-L178) [_agents.py#L1751-L1845](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1751-L1845)
- Concretely, Java is better off collecting the public surface into a single `Agent` while internally keeping `DelegatingAgent`/`AgentBuilder` as in `.NET`. Only then can logging, telemetry, and policy wrappers be composed independently. [DelegatingAIAgent.cs#L13-L28](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L13-L28) [LoggingAgent.cs#L16-L31](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/LoggingAgent.cs#L16-L31)
- For the run API shape, .NET-style **explicit separation of async methods** suits Java better than the Python style of “a synchronous method returning an awaitable/stream”. In Java, separating `runAsync()` and `streamAsync()` makes checked/unchecked error handling, cancellation, and the reactive stream choice clearer. [AIAgent.cs#L251-L506](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L251-L506) [_agents.py#L983-L1040](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L983-L1040)
- For session snapshot ownership, rather than choosing between the agent-owned format (.NET) and the session-owned format (Python), a **dual structure where the agent validates compatibility and the session/store keeps the payload** suits Java. This satisfies both the per-agent session compatibility check and the generic session snapshot store requirement at the same time. [AIAgent.cs#L168-L235](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L168-L235) [_sessions.py#L1655-L1689](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1655-L1689)
