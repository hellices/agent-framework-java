# 10. Middleware

## 1. Status

The middleware surface at this commit comes in two branches. **.NET** is a builder-centric structure that wraps `AIAgent`/`IChatClient` in decorators, and **Python** is centred on the 3-seam typed pipeline of `AgentMiddleware`/`ChatMiddleware`/`FunctionMiddleware`. Adjacent features such as message injection, tool approval, per-service-call persistence, and agent-hooks are also bound in through these middleware seams. ([AIAgentBuilder](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L13-L178), [ChatClient default stack](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L52-L139), [Python middleware seams](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L477-L681), [Python session injection middleware](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1279-L1432), [agent-hooks bundle intro](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agent_hooks.py#L3-L20))

## 2. Purpose and boundary

The purpose of middleware is to **observe or change the input, state, and result before and after** an agent run, a chat model call, and a function/tool invocation, and to short-circuit when necessary. .NET provides this through `DelegatingAIAgent` and `AIAgentBuilder.Use(...)`, and Python solves the same purpose with per-seam middleware protocols that receive a context object and `call_next()`. ([DelegatingAIAgent remarks](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L13-L27), [AIAgentBuilder Use overloads](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L72-L178), [AgentMiddleware docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L477-L533), [FunctionMiddleware docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L536-L597), [ChatMiddleware docs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L600-L662))

This document includes the following.

- The .NET agent/function/chat middleware builder and decorator structure
- Python contexts/layers/bundles/decorators
- ordering/nesting, `next` invocation, mutation, termination, exception behavior
- async/streaming/cancellation
- The **contact points** between hooks and message injection/tool approval

This document does not restate the following.

- The detailed payload contract of the tool approval request/response
- The whole user experience/sample procedure of message injection

It records only **where** middleware connects to approval/message injection instead. .NET wires the approval/message injection/persistence toggles in `ChatClientAgentOptions`, while in Python a function middleware can return an approval request or observe a replay approval response through `metadata["approval_response"]`, and a chat middleware drains the session queue. ([ChatClientAgentOptions approval/message injection flags](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgentOptions.cs#L95-L276), [Python function approval touchpoint](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L1576-L1626), [Python message injection touchpoint](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1298-L1432))

## 4. APIs and types

### 4.1 .NET

- **Agent seam**: `AIAgentBuilder.Use(...)` takes (1) a `Func<AIAgent, AIAgent>`, (2) a `Func<AIAgent, IServiceProvider, AIAgent>`, (3) a shared run delegate, and (4) a `runFunc`/`runStreamingFunc` pair. Agent-level middleware is therefore exposed as a **decorating agent** or as **run delegate interception** rather than as a “typed context object”. ([AIAgentBuilder overloads](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L72-L178))
- **Decorator base**: `DelegatingAIAgent` transparently delegates `Id/Name/Description/GetService/Run/CreateSession/Serialize/Deserialize` to the inner agent. Middleware uses the pattern of inheriting this base and overriding only some methods. ([DelegatingAIAgent](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L28-L102))
- **Function seam**: the callback shape of the public extension is `Func<AIAgent, FunctionInvocationContext, Func<FunctionInvocationContext, CancellationToken, ValueTask<object?>>, CancellationToken, ValueTask<object?>>`. This seam can only be attached when a `FunctionInvokingChatClient` is present. ([function middleware extension signature](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgentBuilderExtensions.cs#L16-L52))
- **Chat seam (observable surface)**: the contract visible in this repo is `chatClient.AsBuilder().Use(...).Build()` and the `ChatClientAgentOptions` based default stack composition. The sample and `WithDefaultAgentMiddleware()` both consume the same shape. ([sample chat builder usage](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/samples/02-agents/Agents/Agent_Step11_Middleware/Program.cs#L36-L53), [default chat stack builder usage](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L52-L139))
- **Built-in decorators**: `LoggingAgent`, `OpenTelemetryAgent`, `MessageInjectingChatClient`, `PerServiceCallChatHistoryPersistingChatClient`, and the approval-binding/bypass decorators act as prebuilt middleware. ([LoggingAgent](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/LoggingAgent.cs#L16-L174), [OpenTelemetryAgent](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/OpenTelemetryAgent.cs#L15-L214), [MessageInjectingChatClient](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L14-L391), [default stack order](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L56-L127))

### 4.2 Python

- **Context types**: `AgentContext` has `messages/session/tools/options/stream/result/metadata/client_kwargs/function_invocation_kwargs/stream_*_hooks`, `FunctionInvocationContext` has `function/arguments/session/result/metadata/kwargs/tools`, and `ChatContext` has `client/messages/options/session/result/metadata/kwargs/function_invocation_kwargs/stream_*_hooks`. ([AgentContext](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L96-L210), [FunctionInvocationContext](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L212-L378), [ChatContext](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L381-L475))
- **Per-seam middleware protocols**: `AgentMiddleware`, `FunctionMiddleware`, and `ChatMiddleware` all require an asynchronous `process(context, call_next)` method. ([middleware ABCs](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L477-L662))
- **Function decorators**: `@agent_middleware`, `@function_middleware`, and `@chat_middleware` attach a `_middleware_type` marker, and an unmarked callable is classified by the annotation of its first parameter. ([decorators](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L766-L862), [type determination](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1548-L1616))
- **Bundle/layer types**: `MiddlewareBundle` binds several seams into one indivisible feature, and `AgentMiddlewareLayer`/`ChatMiddlewareLayer` classify, forward, and cache middleware at runtime. ([MiddlewareBundle](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L680-L752), [ChatMiddlewareLayer](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1202-L1355), [AgentMiddlewareLayer](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1357-L1545))

## 5. Execution flow

### 5.1 .NET ordering / nesting

1. `AIAgentBuilder.Build()` applies the factories **in reverse order**, so what was `Use()`d first becomes the outermost. ([AIAgentBuilder.Build](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L49-L69))
2. `DelegatingAIAgent` fully delegates to the inner agent by default, and an individual decorator intervenes only in specific methods. ([DelegatingAIAgent](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/DelegatingAIAgent.cs#L66-L102))
3. Function middleware enters the execution path through `FunctionInvocationDelegatingAgent` overwriting the `ChatClientFactory` to turn the `AIFunction` entries of the tool list into `MiddlewareEnabledFunction` objects. The callback calls `next(context, cancellationToken)` to proceed to the actual tool invocation. ([FunctionInvocationDelegatingAgent](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgent.cs#L24-L88))
4. The order of the default chat stack, per the source comment, is `ApprovalResponseBinding` → `ApprovalNotRequiredFunctionBypassing` → optional `InvocableFunctionBypassing` → `FunctionInvokingChatClient` → optional `MessageInjectingChatClient` → optional `PerServiceCallChatHistoryPersistingChatClient` → `DeferredOpenTelemetryChatClient`. ([default chat stack order](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientExtensions.cs#L56-L127))
5. The sample shows a real composition example that **nests chat-client middleware, agent-run middleware, function middleware, and per-request middleware as separate layers**. ([middleware sample](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/samples/02-agents/Agents/Agent_Step11_Middleware/Program.cs#L36-L132))

### 5.2 Python ordering / nesting

1. `categorize_middleware()` normalizes bare sources, then expands bundles and classifies them into the agent/function/chat categories. ([categorize_middleware](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1625-L1734))
2. `AgentMiddlewareLayer.run()` keeps the agent middleware on the outside and forwards the chat/function middleware to the underlying chat-client stack through `client_kwargs["middleware"]`. ([AgentMiddlewareLayer.run](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1450-L1545))
3. The pre-order of each pipeline is the registration order, and the post-order is the reverse. ([pipeline execution](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L974-L1190), [ordering tests](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_middleware.py#L973-L1104))
4. Mixed run-level middleware is split per loop. Chat middleware applies to **each model round** and function middleware to **each tool invocation**. ([chat/function split source](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_tools.py#L3238-L3335), [non-streaming split test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_middleware_with_chat.py#L850-L921), [streaming split test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_middleware_with_chat.py#L923-L1001))
5. agent-hooks makes its three agent/chat/function middleware private and ships them only through a `MiddlewareBundle`. ([agent-hooks bundle intro](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agent_hooks.py#L8-L20), [bundle build](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agent_hooks.py#L1612-L1617))

## 6. State

### 6.1 .NET

- `ChatClientAgent` holds a clone of the mutable `ChatClientAgentOptions`, and keeps the wrapped `ChatClient` when the default stack is enabled. ([ChatClientAgent ctor](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs#L118-L146))

([MessageInjectingChatClient state and locking](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L44-L61), [enqueue/drain helpers](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L180-L329))

([conversation id propagation](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L104-L109), [options cloning helper](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L370-L390))
- The function middleware decorator promotes a bare `AgentRunOptions` into a `ChatClientAgentRunOptions` while preserving `ResponseFormat`, `AllowBackgroundResponses`, `ContinuationToken`, and `AdditionalProperties`. ([conversion code](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/FunctionInvocationDelegatingAgent.cs#L30-L67), [preservation test](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.UnitTests/FunctionInvocationDelegatingAgentTests.cs#L940-L988))

### 6.2 Python

- `AgentContext`/`ChatContext`/`FunctionInvocationContext` all have `metadata` and a mutable `result`, and these objects become the shared state/override surface of Python middleware. ## 14. Java typed interceptor decision and the Spring integration boundary

### 14.1 Decision

The Java porting decision of this document is to **adopt the Python-style 3-seam typed interceptor as the first-class public API and to provide the .NET-style prebuilt decorators alongside it as a convenience layer**. The rationale is that the Python source exposes the context, result, ordering, and partial-install rules of agent/chat/function most transparently, while the .NET source shows the operational pattern of providing cross-cutting concerns such as logging/telemetry as prebuilt decorators. ([Python seam contexts](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L96-L475), [Python category enforcement](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1643-L1734), [Python agent→chat/function forwarding](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1454-L1472), [UseLogging](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/LoggingAgentBuilderExtensions.cs#L17-L65), [UseOpenTelemetry](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/OpenTelemetryAgentBuilderExtensions.cs#L13-L58))

The recommended public shape is as follows.

- `AgentInterceptor` — run-level input/output, metadata, stream/result hooks
- `ChatInterceptor` — model-call messages/options/result
- `FunctionInterceptor` — validated tool args/result/live tools mutation
- `InterceptorBundle` — an opaque unit that binds a multi-seam feature such as agent-hooks so that it cannot be installed partially

Only this way can the core runtime keep owning a **session-backed state machine** such as approval/message injection while concerns such as logging/telemetry/redaction are easily wrapped in a Spring-friendly wrapper. ([Python bundle invariants](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L680-L752), [Python message injection session ownership](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_sessions.py#L1298-L1432), [.NET message injection session ownership](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L24-L61))

### 14.2 Spring integration boundary

Spring should take charge only as far as **bean discovery / ordering / conditional auto-configuration**. The following must stay inside the core runtime boundary.

- The interceptor pre/post ordering and the outermost/innermost rules
- session state bag / queue ownership
- approval/message injection/persistence state machine
- gated stream sealing rules

That is, Spring AOP or a BeanPostProcessor must not directly reconstruct the tool/message approval state or reinterpret the interceptor order. Spring takes charge only of sorting `List<AgentInterceptor>`, registering convenience decorator beans, and observability bean wiring, and the execution contract must be fixed by the framework core. ([AIAgentBuilder outermost rule](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/AIAgentBuilder.cs#L54-L67), [Python supported-category enforcement](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_middleware.py#L1655-L1734), [MessageInjectingChatClient session queue](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI/ChatClient/MessageInjectingChatClient.cs#L180-L329), [ResponseStream sealing](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3552-L3624))
