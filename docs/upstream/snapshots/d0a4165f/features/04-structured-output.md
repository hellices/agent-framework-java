# 04-structured-output

This document covers only the **structured response type/schema**, **provider capability**, **native vs fallback behavior**, **parsing/validation**, **streaming constraints**, **error handling**, and the **.NET/Python drift** of the agent core. .NET exposes structured output through `AIAgent.RunAsync<T>()` and `AgentResponse<T>.Result`, while Python exposes it through `ChatOptions["response_format"]` and the lazy parsing of `ChatResponse.value`/`AgentResponse.value`. Both implementations share the point that “a structured response can be requested from the provider”, but they differ in that .NET is centred on a **non-streaming typed API** while Python is centred on a **response-level lazy parse**. [AIAgentStructuredOutput.cs#L13-L139](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L13-L139) [AgentResponse{T}.cs#L18-L98](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L18-L98) [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494) [_types.py#L2742-L2764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2742-L2764)

## Purpose

The purpose of this feature is to request the model response as **data conforming to a specific type or JSON schema** rather than as free text, and to hand it to the caller as a typed value. .NET builds the structured output request with `ChatResponseFormat.ForJsonSchema<T>()` and injects it into the request options, while Python puts a `response_format` field into the common `ChatOptions` and parses the final assistant text into a Pydantic model or a JSON mapping. [AIAgentStructuredOutput.cs#L127-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L127-L138) [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201) [_types.py#L3708-L3727](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3708-L3727)

## Structured response type/schema

### .NET

- .NET builds the schema with `ChatResponseFormat.ForJsonSchema<T>(serializerOptions)` and puts it into the request `ResponseFormat`. [AIAgentStructuredOutput.cs#L127-L134](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L127-L134)

### Python

- Python keeps `response_format` only as a type or a mapping and does not build a separate schema wrapper model. ## Native vs fallback behavior

### .NET

- The native path is the case where the provider honours `ResponseFormat` and directly generates text conforming to the JSON schema. `RunAsync<T>()` injects the schema, and `AgentResponse<T>.Result` then deserializes that text. [AIAgentStructuredOutput.cs#L127-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L127-L138) [AgentResponse{T}.cs#L55-L73](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L73)
- Fallback 1: even when a non-object wrapper is expected but the provider returns a bare primitive instead of `{"data":...}`, `Result` can fall back to the original JSON. A pinned test verifies this behavior. [AIAgentStructuredOutputTests.cs#L221-L236](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AIAgentStructuredOutputTests.cs#L221-L236)
- Fallback 2: to work around the problem where some LLM backends emit multiple top-level JSON objects after a function call, .NET deserializes only the first top-level object. This is a parser-side fallback that absorbs provider drift in structured output. [AgentResponse{T}.cs#L76-L97](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L76-L97)
- If the provider ignores the schema and returns non-JSON text, on the other hand, the framework does not synthesize a separate structured fallback. An exception is ultimately raised on `Result` access. [AgentRunOptions.cs#L102-L108](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRunOptions.cs#L102-L108) [AgentResponse{T}.cs#L55-L69](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L69)

### Python

- The native path is the case where the provider takes `response_format` and actually generates structured JSON text. The core parses it in the final `value` property without a separate typed run overload. [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494) [_types.py#L2742-L2764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2742-L2764)
- Fallback 1: even when the provider does not specifically implement a native structured mode, `value` is produced as long as it returns valid JSON text. The fake client tests show this path. [test_agents.py#L329-L345](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_agents.py#L329-L345) [test_agents.py#L348-L372](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_agents.py#L348-L372)
- Fallback 2: `value` does not parse `Message.text` or `response.text` as is; it parses the string that `_last_non_empty_assistant_message_text()` builds by directly concatenating the text fragments of the assistant message contents. Thanks to this, the parse can succeed even when `Message.text` has been damaged by inserting whitespace between structured JSON chunks. [ _types.py#L2204-L2211](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2204-L2211) [test_types.py#L910-L944](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L910-L944)
- Fallback 3: even when there are multiple assistant messages or a trailing tool message, Python takes only the **last non-empty assistant message** as the structured parse target. [ _types.py#L2204-L2211](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2204-L2211) [test_types.py#L921-L933](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L921-L933) [test_types.py#L985-L1010](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L985-L1010)

## Parsing / validation

### .NET

- `AgentResponse<T>.Result` throws `InvalidOperationException("The response did not contain JSON...")` when `Text` is empty, and throws `InvalidOperationException("The deserialized response is null.")` when the deserialize result is null. [AgentResponse{T}.cs#L55-L69](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L69)
- The pinned tests verify that empty text and a `"null"` payload each raise an exception. [AIAgentStructuredOutputTests.cs#L238-L265](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AIAgentStructuredOutputTests.cs#L238-L265)
- The object/non-object unwrap behavior itself is verified by tests as well. The `{"data":...}` wrapper of a primitive, an array, and an enum is unwrapped correctly. [AIAgentStructuredOutputTests.cs#L167-L218](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AIAgentStructuredOutputTests.cs#L167-L218)

### Python

- `_parse_structured_response_value()` returns `None` when `response_format is None` or the text is empty. For a Pydantic type it uses `model_validate_json`, and for a mapping it uses `json.loads`. [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201)
- A mapping parse failure is converted into `ValueError("Response text is not valid JSON: ...")`. [_types.py#L2191-L2195](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2191-L2195)
- The pinned tests verify that empty text returns `None` and that a Pydantic schema violation propagates the `ValidationError` as is. [test_types.py#L1013-L1036](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L1013-L1036) [test_types.py#L1039-L1072](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L1039-L1072)
- As an important implementation difference, Python's `ChatResponse.value` and `AgentResponse.value` do not parse until the caller reads that property. Malformed structured output can therefore let the run itself succeed and fail only at `value` access time. ## Errors and the .NET/Python drift

### Core drift 1: where the typed API sits

- In .NET, typedness is attached to the **run API**. `RunAsync<T>()` builds the request schema and the typed response together. [AIAgentStructuredOutput.cs#L34-L139](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L34-L139)
- In Python, typedness is attached to a **response object property**. The run API is untyped, and the final `value` access triggers the parse. [_agents.py#L1766-L1828](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_agents.py#L1766-L1828) [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494)

### Core drift 2: non-object schema handling

- .NET wraps a primitive/array/enum into a wrapper object. [AIAgentStructuredOutput.cs#L129-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L129-L138)
- Python builds no separate wrapper and parses the final assistant text as is. [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201)

### Core drift 3: empty/invalid structured output

- .NET treats empty text or a null deserialize as an **exception**. [AgentResponse{T}.cs#L55-L69](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L69) [AIAgentStructuredOutputTests.cs#L238-L265](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AIAgentStructuredOutputTests.cs#L238-L265)
- Python returns `None` for empty text. Invalid JSON becomes a `ValueError` on the mapping parse, and a schema mismatch becomes a `ValidationError`. [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201) [test_types.py#L1013-L1072](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L1013-L1072)

### Core drift 4: choosing the text to parse

- .NET parses the whole response `Text` in `AgentResponse<T>.Result`. [AgentResponse{T}.cs#L55-L66](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L66)

[_types.py#L2204-L2211](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2204-L2211) [test_types.py#L921-L933](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L921-L933) [test_types.py#L985-L1010](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L985-L1010)

## Java decisions

- Java has to choose between a **typed request API** as in .NET and a **response-level lazy parse** as in Python. Compromising between the two implementations, it is reasonable for `run()` to return an untyped response and to provide a separate `runStructured(Class<T>|Schema<T>)` or `response.as(Class<T>)`. That way both .NET's explicit request semantics and Python's flexible parse semantics can be taken. [AIAgentStructuredOutput.cs#L34-L139](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L34-L139) [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494)
- For non-object schema handling, adopting the wrapper object strategy as .NET does is more explicit in Java. The Python-style bare JSON parse is simple, but the wire-level contract is weak when a primitive/array/enum response has to be requested from the provider unambiguously. [AIAgentStructuredOutput.cs#L129-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L129-L138) [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201)
- For the validation policy it is better to separate a **Pydantic/typed schema route** and a **mapping/JSON-only route** as Python does. In Java the typed schema route can be Bean Validation / Jackson binding and the JSON-only route can be a raw `JsonNode` or `Map<String,Object>` parse. [_types.py#L2186-L2195](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2186-L2195) [test_types.py#L1039-L1072](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_types.py#L1039-L1072)
- For streaming structured output it is conservative not to have an official typed streaming API, as in .NET. It is simpler for Java too to provide the typed final response only at finalization after the stream ends. [AIAgent.cs#L382-L506](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs#L382-L506) [test_agents.py#L265-L326](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_agents.py#L265-L326)
