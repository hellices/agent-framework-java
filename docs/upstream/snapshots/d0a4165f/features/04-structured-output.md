# 04-structured-output

이 문서는 Agent core의 **structured response type/schema**, **provider capability**, **native vs fallback behavior**, **parsing/validation**, **streaming 제약**, **오류 처리**, 그리고 **.NET/Python drift**만 다룬다. .NET은 `AIAgent.RunAsync<T>()`와 `AgentResponse<T>.Result`로 structured output을 노출하고, Python은 `ChatOptions["response_format"]`와 `ChatResponse.value`/`AgentResponse.value`의 lazy parsing으로 structured output을 노출한다. 두 구현 모두 “provider에 구조화 응답을 요청할 수 있다”는 공통점은 있지만, .NET은 **non-streaming typed API 중심**, Python은 **response-level lazy parse 중심**이라는 차이를 가진다. [AIAgentStructuredOutput.cs#L13-L139](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L13-L139) [AgentResponse{T}.cs#L18-L98](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L18-L98) [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494) [_types.py#L2742-L2764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2742-L2764)

## 목적

이 기능의 목적은 모델 응답을 단순 자유 텍스트가 아니라 **특정 타입 또는 JSON schema에 맞는 데이터**로 요청하고, 이를 호출자에게 typed value로 전달하는 것이다. .NET은 structured output 요청을 `ChatResponseFormat.ForJsonSchema<T>()`로 생성해 request option에 주입하고, Python은 `response_format` 필드를 공통 `ChatOptions`에 넣고 최종 assistant text를 Pydantic model 또는 JSON mapping으로 파싱한다. [AIAgentStructuredOutput.cs#L127-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L127-L138) [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201) [_types.py#L3708-L3727](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L3708-L3727)

## Native vs fallback behavior

### .NET

- native path는 provider가 `ResponseFormat`을 honor하여 JSON schema에 맞는 text를 직접 생성하는 경우다. `RunAsync<T>()`는 schema를 주입하고, 이후 `AgentResponse<T>.Result`가 그 text를 deserialize한다. [AIAgentStructuredOutput.cs#L127-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L127-L138) [AgentResponse{T}.cs#L55-L73](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L73)
- fallback 1: non-object wrapper가 기대되지만 provider가 `{"data":...}` 대신 bare primitive를 반환해도 `Result`는 원본 JSON으로 fallback할 수 있다. pinned test가 이 동작을 검증한다. [AIAgentStructuredOutputTests.cs#L221-L236](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/tests/Microsoft.Agents.AI.Abstractions.UnitTests/AIAgentStructuredOutputTests.cs#L221-L236)
- fallback 2: 일부 LLM backend가 function-call 뒤 여러 top-level JSON object를 내는 문제를 우회하기 위해, .NET은 첫 top-level object만 deserialize한다. 이는 structured output의 provider drift를 흡수하는 parser-side fallback이다. [AgentResponse{T}.cs#L76-L97](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L76-L97)
- 반면 provider가 schema를 무시해 비-JSON text를 반환하면 framework가 별도 구조화 fallback을 합성하지는 않는다. 결국 `Result` access에서 예외가 난다. [AgentRunOptions.cs#L102-L108](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRunOptions.cs#L102-L108) [AgentResponse{T}.cs#L55-L69](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AgentResponse%7BT%7D.cs#L55-L69)

### Python

- native path는 provider가 `response_format`을 받아 실제로 structured JSON text를 생성하는 경우다. core는 별도 typed run overload 없이 final `value` property에서 이를 파싱한다. [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494) [_types.py#L2742-L2764](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2742-L2764)
- fallback 1: provider가 native structured mode를 특별히 구현하지 않아도, valid JSON text만 돌려주면 `value`는 만들어진다. fake client tests가 이 경로를 보여준다. [test_agents.py#L329-L345](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_agents.py#L329-L345) [test_agents.py#L348-L372](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/tests/core/test_agents.py#L348-L372)
- fallback 2: `value`는 `Message.text` 또는 `response.text`를 그대로 parse하지 않고, `_last_non_empty_assistant_message_text()`가 assistant message contents의 text 조각을 직접 이어 붙인 문자열을 parse한다. 이 덕분에 `Message.text`가 구조화 JSON chunk 사이에 공백을 넣어 손상된 경우에도 parse가 성공할 수 있다. ## Java 결정

- Java는 .NET처럼 **typed request API**와 Python처럼 **response-level lazy parse** 중 하나를 선택해야 한다. 두 구현을 절충하면 `run()`은 untyped response를 주고, 별도 `runStructured(Class<T>|Schema<T>)` 또는 `response.as(Class<T>)`를 제공하는 것이 합리적이다. 이렇게 하면 .NET의 명시적 요청 semantics와 Python의 유연한 parse semantics를 함께 취할 수 있다. [AIAgentStructuredOutput.cs#L34-L139](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L34-L139) [_types.py#L2473-L2494](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2473-L2494)
- non-object schema 처리는 Java에서 .NET처럼 wrapper object 전략을 채택하는 편이 명시적이다. Python식 bare JSON parse는 간단하지만, primitive/array/enum response를 provider에게 명확히 요청할 때 wire-level 계약이 약하다. [AIAgentStructuredOutput.cs#L129-L138](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgentStructuredOutput.cs#L129-L138) [_types.py#L2181-L2201](https://github.com/microsoft/agent-framework/blob/d0a4165f170193ba1d026a259af40d35bb7eaefe/python/packages/core/agent_framework/_types.py#L2181-L2201)
